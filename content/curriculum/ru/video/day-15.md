## Видео — это мультик на полях тетради

Помнишь, как в школе рисовали человечка на уголках страниц и быстро их листали? Видео устроено так же.

- **Кадр** — одна картинка.
- **fps** (кадров в секунду) — сколько картинок показывают за секунду. 24 — «киношно», 30 — стандарт для интернета,
  60 — плавно, для записи экрана и игр. **Длительность = кадры ÷ fps.** 90 кадров при 30 fps — ровно 3 секунды.
- **Разрешение** — размер кадра в пикселях. 1920×1080 — горизонталь 16:9 (обычный YouTube, VK Видео).
  1080×1920 — вертикаль 9:16 (Shorts, VK Клипы, Reels).
- **Кодек** — способ, которым картинки сжимают. **H.264** играет везде: в браузере, в Telegram, на старом
  телевизоре. H.265, VP9 и AV1 сжимают сильнее, но поддерживаются не везде.
- **Контейнер** — коробка, в которой лежат сжатое видео, звук и служебная информация: `.mp4`, `.mov`, `.webm`.

Проще всего так: контейнер — это посылка, кодек — то, как вещи упаковали внутри. В коробке `.mp4` может лежать и
H.264, и AV1. Поэтому «это же mp4» ещё не значит, что файл откроется у бабушки на телевизоре.

Ещё два слова из каждой команды: **CRF** — качество для H.264 (18 — отлично, 23 — по умолчанию, чем больше, тем
меньше файл и мыльнее картинка) и **формат пикселей** `yuv420p` — раскладка цвета, которую понимает любой телефон.

## Шаг 1. Рисуем 90 кадров и склеиваем

Открой свою мастерскую для видео с 14-го дня (`~/66/video`) и создай в ней папку `day15/`. До 27-го дня все пути в
треке — относительно `~/66/video`. Сначала заведи в мастерской одно Python-окружение на весь трек — тот же приём с
`.venv`, что на 12-й день, чтобы pip не ругался «externally-managed-environment»:

```bash
cd ~/66/video
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install pillow
```

Активируй его в каждом новом терминале перед запуском скриптов (в начале строки появится `(.venv)`) и допиши в
`CLAUDE.md` мастерской строку: «Python-пакеты ставим в ~/66/video/.venv». Дальше любое «установи» в промпте значит —
в это окружение. Теперь задание агенту:

```text
Цель: Python-скрипт, который рисует 90 PNG-кадров для трёхсекундной анимации.
Контекст: я учусь собирать видео из кадров. Папка day15/. Python 3 и Pillow установлены в ~/66/video/.venv (оно активно).
Ограничения:
- 1920x1080, тёмный фон, по центру прогресс-бар, который заполняется от 0 до 100 % за 90 кадров, над ним крупно — текущий процент.
- В левом верхнем углу — номер кадра, чтобы было видно отдельные кадры.
- Сохраняй как day15/frames/frame_0000.png ... frame_0089.png (нумерация с нуля, четыре цифры).
- ffmpeg не вызывай — склею сам.
Готово, когда: `python day15/make_frames.py` создаёт ровно 90 PNG и пишет, сколько файлов сохранил.
```

Запусти, открой пару кадров — они должны отличаться. Теперь склей видео руками:

```bash
ffmpeg -framerate 30 -i day15/frames/frame_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 day15/progress.mp4
```

`-framerate 30` — с какой скоростью читать картинки, `%04d` — «номер из четырёх цифр», `-pix_fmt yuv420p` — чтобы
файл играл везде. Проверь, что получилось:

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames,pix_fmt -show_entries format=duration -of default=noprint_wrappers=1 day15/progress.mp4
```

Должно быть: `codec_name=h264`, `width=1920`, `height=1080`, `r_frame_rate=30/1`, `nb_frames=90`,
`duration=3.000000`. Загрузи `progress.mp4` как доказательство.

> **Если застрял:** «No such file» почти всегда значит, что шаблон не совпадает с именами: проверь, что первый файл
> действительно `frame_0000.png`. «height not divisible by 2» — нечётный размер кадра, а H.264 с yuv420p требует
> чётных ширины и высоты. Кидай агенту полный текст ошибки и проси объяснить причину, а не просто «почини».

## Шаг 2. Четыре команды на все случаи жизни

Сделай тестовый звук, чтобы ничего не скачивать:

```bash
ffmpeg -f lavfi -i "sine=frequency=440:duration=3" day15/beep.wav
```

Прогони каждую команду на `progress.mp4`, проверь результат через ffprobe и сложи все четыре в `day15/CHEATSHEET.md`
с короткой подписью: что делает.

```bash
# 1. Обрезка: начиная с 0,5 с, оставить 2 с (с перекодированием — режет точно по кадру)
ffmpeg -ss 0.5 -i day15/progress.mp4 -t 2 -c:v libx264 -crf 18 -pix_fmt yuv420p day15/trim.mp4

# 2. Вписать в вертикаль 1080x1920 с полями (без растягивания и обрезки)
ffmpeg -i day15/progress.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2:color=black,setsar=1" -c:v libx264 -crf 18 -pix_fmt yuv420p day15/vertical.mp4

# 3. Добавить звук: видео не трогаем, звук — в AAC, длина по короткому потоку
ffmpeg -i day15/progress.mp4 -i day15/beep.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest day15/with-audio.mp4

# 4. Красивая GIF: сначала своя палитра, потом её применение
ffmpeg -i day15/progress.mp4 -vf "fps=15,scale=480:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" day15/progress.gif
```

Зачем GIF два прохода: в GIF помещается только 256 цветов. `palettegen` подбирает лучшие 256 под *твоё* видео,
`paletteuse` их применяет. Без этого получатся грязные полосы на градиентах.

> **Совет:** `-c copy` (без перекодирования) работает мгновенно, но режет только по ключевым кадрам, поэтому обрезка
> съезжает. Нужна точность — перекодируй, как в команде 1.

## Мини-тест

1. 90 кадров, 30 fps. Сколько длится видео?
2. Нужен ролик на 12 секунд при 24 fps. Сколько кадров должен нарисовать скрипт?
3. Те же 90 кадров проиграли при 60 fps. Что изменится?
4. В видео на 30 fps в какой момент появится кадр номер 45 (считая с нулевого)?

> **Ответы:**
>
> 1. 3 секунды (90 ÷ 30).
> 2. 288 кадров (12 × 24).
> 3. Видео станет длиной 1,5 секунды, движение — вдвое быстрее: кадры те же, времени меньше.
> 4. На 1,5 секунды (45 ÷ 30). Нулевой кадр — это 0,0 с.
