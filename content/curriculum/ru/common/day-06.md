Агенты быстрые, а значит, и рабочую страницу могут угробить за десять секунд. Выход не в том, чтобы доверять им
меньше, а в том, чтобы любой эксперимент было дёшево отменить. В этом и есть настоящая работа git. После сегодняшнего
дня ты будешь отпускать агента в самые дикие идеи — и спать спокойно.

## Коммиты, ветки и зачем они агентам

**Коммит** — снимок всей папки с подписью. Коммиты выстраиваются в историю, которую можно читать
(`git log --oneline`), сравнивать (`git diff`) и к которой можно вернуться.

**Ветка** — параллельная реальность. `main` — основная, именно её показывает GitHub Pages. Создаёшь ветку `redesign`
— и все коммиты в ней не касаются `main`, пока ты не решишь их **влить** (merge). Не понравилось? Удаляешь ветку, а
`main` ничего и не заметила. Как черновик, который можно скомкать.

Пять команд закрывают 90% жизни:

```bash
git status                 # что изменилось с последнего коммита?
git diff                   # покажи конкретные строки
git log --oneline          # история, по строке на коммит
git switch -c redesign     # создать ветку и перейти на неё
git switch main            # вернуться в main
```

> **Совет:** перед любой крупной задачей для агента закоммить то, что есть. Чистая точка старта — лучшая кнопка
> «отменить».

## Шаг 1. Редизайн на ветке (25 минут)

Убедись, что всё закоммичено (`git status` пишет «nothing to commit»), и:

```bash
cd ~/66-day-promise
git switch -c redesign
claude
```

```text
Цель: смелый редизайн моей страницы-обещания. Попробуй совсем другой облик: новую
раскладку, другое цветовое настроение, другую типографику. Удиви меня.

Контекст: мы на git-ветке redesign, так что менять можно много.

Ограничения: весь текст и счётчик дней должны остаться и работать. По-прежнему один
index.html, читается при ширине 390px и в тёмной теме.

Готово, когда: страница открыта в моём браузере, а редизайн закоммичен в ветке redesign.
Не вливай в main и не пушь.
```

Посмотри. Теперь попрыгай между реальностями и обновляй браузер после каждого переключения:

```bash
git switch main        # старый дизайн
git switch redesign    # новый дизайн
```

Решай. **Оставить:**

```bash
git switch main
git merge redesign
git push
```

**Выбросить:**

```bash
git switch main
git branch -D redesign
```

Любой вариант — победа. Ты только что провёл эксперимент без малейшего риска.

**Доказательство:** вывод `git log --oneline` из ветки `main` и одна строка о том, что ты решил и почему.

## Шаг 2. Сломай и почини (20 минут)

**Ломаем до коммита.** Открой `index.html`, удали весь блок `<style>…</style>`, сохрани, обнови страницу. Красота,
да? Теперь:

```bash
git status                  # index.html помечен как modified
git diff                    # красные строки — всё, что ты удалил
git restore index.html      # назад к последнему коммиту
```

Обнови страницу. Спасено.

**Ломаем после коммита.** Попроси агента: `поменяй заголовок на «упс» и закоммить как "break on purpose"`, затем
`git push`. Через минуту живой сайт тоже скажет «упс». Отменяем:

```bash
git revert --no-edit HEAD   # новый коммит, который отменяет предыдущий
git push
```

`revert` не стирает историю, а добавляет коммит-отмену. Для всего, что уже запушено, — именно то, что нужно.

> **Если застрял:** git открыл странный текстовый экран и просит сообщение коммита? Это редактор Vim. Набери `:wq`
> и нажми Enter — сохранится сообщение по умолчанию. Совсем запутался? Выполни `git status` и отдай вывод агенту
> со словами «объясни, где я, и как вернуться в чистый main».

**Доказательство:** вставь команды, которые выполнял, и последние три строки `git log --oneline`.

## Мини-тест

Какая команда нужна?

1. Ты поменял файл, не закоммитил и хочешь вернуть как было.
2. Неудачный коммит уже на GitHub, живой сайт сломан.
3. Хочется попробовать рискованную идею, не трогая живой сайт.
4. Перед коммитом хочешь увидеть, какие именно строки поменял агент.

<details><summary>Ответы</summary>

1. `git restore <файл>` — выбрасывает незакоммиченные изменения в этом файле.
2. `git revert HEAD`, затем `git push` — добавляет коммит-отмену, история остаётся честной.
3. `git switch -c experiment` — отдельная ветка; `main` и Pages не тронуты.
4. `git diff` — все добавленные и удалённые строки.

Есть ещё `git reset --hard`: он отматывает назад и *стирает*. Мощная и опасная штука — пока не трогай и никогда не
применяй к тому, что уже запушено.

</details>
