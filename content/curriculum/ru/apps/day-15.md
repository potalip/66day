Ближайшие тринадцать дней ты растишь **одно** приложение. Не очередной список дел из туториала, а инструмент против
настоящей занозы, которая колет живого человека (возможно, тебя) каждую неделю. На 27-й день им будут пользоваться трое.
Сегодня ты выбираешь проблему, записываешь её так, чтобы агент не понял её превратно, и кладёшь первый кирпич.

## Как урезать v1 до недели

**Спецификация** (спека) — договор на одну страницу между тобой, тобой-через-неделю и агентом: что именно строим.
Агент блестяще отвечает на вопрос «как» и плохо угадывает «что». Каждая размытая строчка в спеке потом превращается
в час переделок.

Хорошая первая версия — это один пользователь, одна задача, один главный экран. Фильтр из четырёх пунктов:

- **Настоящая:** человек с этой проблемой есть у тебя в контактах прямо сейчас. Идеально — тот самый человек с 13-го дня.
- **Частая:** болит хотя бы раз в неделю, значит, к приложению будут возвращаться.
- **Текстовая:** хаос состоит из сообщений, заметок, голосовых, чеков, PDF — ровно того, что ИИ умеет разбирать.
- **Маленькая:** суть укладывается в три пользовательские истории.

Идеи, которые хорошо ложатся на ближайшие две недели (в каждой найдётся список, ИИ-шаг, файлы и «сделай за меня»):

- **Дневник репетитора** — родитель пишет «Маша заболела, давайте перенесём на четверг в пять», а ИИ превращает это
  в перенос занятия; видно, кто сколько должен.
- **Расходы в поездке или после переезда** — траты в лари, драмах, динарах и рублях, всё сводится в одну валюту,
  чек можно сфотографировать.
- **Запись к мастеру** — для знакомого барбера или мастера маникюра: клиенты, окна, напоминания, без вечного
  «а я записывалась?».
- **Счётчики и коммуналка** — показания, платежи, квитанции в PDF; «сколько мы платили за свет прошлой зимой?».
- **Семейный список покупок** — надиктовал голосовое, получил аккуратный список по отделам магазина.

Сквозной пример в этих уроках — дневник репетитора. У тебя должно быть *своё*.

**Пользовательская история** — одно предложение: «Как ___, я хочу ___, чтобы ___». Раздел **«не входит в v1»**
важен не меньше: туда паркуются все блестящие идеи (оплата, команды, мобильное приложение), чтобы v1 всё-таки вышла.

## Шаг за шагом

### 1. Спецификация вместе с агентом (25 минут)

Приложение живёт в `~/66/apps/main-app` — в папке с 14-го дня; сегодня она становится отдельным репозиторием. Дальше во
всех уроках трека «твой репозиторий» — это она:

```bash
mkdir -p ~/66/apps/main-app && cd ~/66/apps/main-app
```

Открой в ней агента (Claude Code или любой другой — Codex CLI, Gemini CLI, Cursor) и заставь его сначала расспросить
тебя, а не додумывать.

```text
Цель: помоги написать спецификацию на одну страницу для небольшого веб-приложения. Код сегодня НЕ пиши.

Контекст: я новичок и строю вместе с агентом. Проблема своими словами:
<3–5 предложений: в чём заноза, у кого она, как с ней справляются сейчас>

Порядок:
1. Сначала задай мне до 8 коротких вопросов одним списком, чтобы убрать неясности. Дождись ответов.
2. Потом напиши docs/SPEC.md ровно с такими разделами: Проблема (3 строки), Для кого (один конкретный человек), Пользовательские истории (ровно 3, «Как… я хочу… чтобы…»), Главный экран (что на нём), Данные (1–2 сущности, которые храним, с полями), Где тут ИИ (одно предложение), Не входит в v1 (минимум 5 пунктов), Готово, когда (проверяемый чек-лист).
3. Не больше 400 слов. Простой язык, без канцелярита и баззвордов.

Перед тем как создавать файл, покажи спеку в чате и дождись моего «ок».
В конце перечитай docs/SPEC.md и скажи, какая строчка всё ещё самая размытая.
```

Отвечай честно: «пока не знаю» — нормальный ответ, и обычно такой пункт уезжает в «не входит в v1». Спорь, если история
похожа на две склеенные.

> **Совет:** если в спеке больше одного главного экрана или в истории дважды встречается «и» — режь.
> Маленькое и выпущенное лучше большого и воображаемого.

### 2. Каркас проекта (25 минут)

Рекомендуемый стек — **Vite + React + TypeScript + Tailwind**, а деплоить позже будем на Cloudflare Workers, как бэкенд
с 11-го дня (Vercel тоже подойдёт). Если React пока пугает, можно и на чистом HTML + JS, но с 29-го дня уроки рассчитаны
на React + Vite + TypeScript. Без веской причины бери React сразу: код всё равно пишет агент.

```text
Цель: разверни каркас проекта для приложения из docs/SPEC.md и сделай первый коммит.

Ограничения:
- Vite + React + TypeScript + Tailwind CSS (по актуальной официальной инструкции из документации Vite и Tailwind).
- Минимум: одна страница с названием приложения и проблемой в одну строку из спеки. Бэкенда пока нет.
- Создай CLAUDE.md в этой папке (и копию AGENTS.md для других агентов): что это за приложение (2 строки, ссылка на docs/SPEC.md), как запустить, и наши правила работы: «сначала объясняй план и жди ок; маленькие коммиты; после каждого изменения запускай приложение и пиши, как именно ты проверил результат».
- В .gitignore обязательно node_modules, dist, .env и .dev.vars.
- Эта папка — отдельный git-репозиторий: если git init здесь ещё не делали, сделай.

Прежде чем что-то запускать, перечисли команды и файлы, которые собираешься создать, и дождись моего «ок».
В конце: собери проект, запусти dev-сервер, назови локальный адрес и покажи `git status` и `git log --oneline`.
```

Открой адрес и убедись, что в браузере видно название твоего приложения. Потом закоммить и выложи код на GitHub через
`gh`, как на 2-й день. Папка остаётся `main-app`, а репозиторий получает настоящее имя приложения (латиницей, через дефис,
например `tutor-diary`):

```bash
git add -A
git commit -m "Scaffold app and add spec"
gh repo create tutor-diary --public --source=. --remote=origin --push
```

Можно и `--private`, если пока не хочешь показывать код.

> **Если застрял:** PowerShell на Windows не даёт запускать `npm`/`npx`? Поправь политику выполнения, как на 11-й день.
> Если `npm run dev` падает, вставь агенту ошибку *целиком* с припиской «воспроизведи, объясни
> причину одним предложением, потом исправь». Если классы Tailwind ничего не меняют — скорее всего, агент взял
> устаревшую настройку; попроси сверить её с текущей документацией Tailwind для Vite.

### 3. Рефлексия (5 минут)

Напиши пару честных предложений: почему именно эта проблема и почему решать её должен ты. «Я третий месяц веду
учеников в заметках и путаюсь, кто оплатил» — отличный ответ. «Мы с соседями по квартире вечно спорим из-за денег,
хочу, чтобы это кончилось» — тоже.

## Готово, когда…

- [ ] Правила урезания прочитаны, проблема выбрана и проходит все четыре фильтра.

- [ ] Каркас запускается локально и запушен, ссылка на репозиторий вставлена.
