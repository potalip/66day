Для большей части твоей аудитории Telegram — это и есть интернет: там новости, работа, родительский чат и доставка
шаурмы. Сегодня твоё приложение переезжает туда же. **Telegram Mini App** — это твой сайт, открытый внутри Telegram
на весь экран, причём пользователь уже известен: ни формы регистрации, ни пароля, ни «подтвердите почту». Бот у тебя
есть с 19-го дня — теперь у него появится кнопка, которая открывает настоящее приложение.

## Как работает Mini App

Это обычный сайт во встроенном браузере Telegram. Telegram подкладывает объект `window.Telegram.WebApp`, а в нём:

- **Параметры темы** — цвета пользователя (`bg_color`, `text_color`, `button_color`…), они же доступны как
  CSS-переменные вроде `var(--tg-theme-bg-color)`. Используешь их — и приложение выглядит родным и в светлой, и в
  тёмной теме.
- **Нативные элементы** — главная кнопка внизу, кнопка «Назад», вибрация, `expand()` на всю высоту.
- **initData** — подписанная строка о том, кто открыл приложение: id, имя, язык, `auth_date` и `hash`.

Вот на последнем пункте держится вся безопасность. Любой может открыть твой адрес в обычном браузере и подсунуть
`initDataUnsafe.user.id = 12345`. Останавливает его **подпись**: Telegram подписывает `initData` ключом, выведенным из
токена твоего бота, а токен знаете только ты и Telegram. Сервер сначала проверяет подпись и только потом верит хоть
одному полю. Простое правило: **клиент рассказывает историю, сервер проверяет паспорт.**

## Шаг за шагом

### 1. Зарегистрируй Mini App (15 минут)

Открой **@BotFather**:

- `/newapp` → выбери бота → название, короткое описание, картинка 640×360 → **HTTPS**-адрес приложения → короткое
  имя. Получишь прямую ссылку вида `https://t.me/tvoy_bot/app`.
- По желанию в настройках бота сделай так, чтобы **кнопка меню** открывала тот же адрес: тогда приложение в одном
  касании от чата.

Telegram принимает только HTTPS. Бери задеплоенное приложение — для тестов отлично подходит превью-деплой на
Cloudflare или Vercel.

### 2. Научи приложение понимать Telegram (35 минут)

```text
Цель: чтобы главное приложение работало как Telegram Mini App и при этом не сломалась обычная веб-версия.
Контекст: задеплоено на <адрес>; фронтенд <фреймворк>; бэкенд <Workers/Node/Python>, аккаунты пользователей уже есть.
Сделай:
1. Подключи официальный скрипт https://telegram.org/js/telegram-web-app.js в <head> до нашего кода
   (в обычном браузере он ничего не ломает). Считай, что мы внутри Telegram, только если WebApp.initData
   не пустой; только тогда вызывай WebApp.ready() и WebApp.expand() и включай всё телеграмное.
2. Сопоставь параметры темы Telegram с нашими дизайн-токенами (фон, текст, подсказки, ссылки, кнопка, текст кнопки),
   чтобы приложение само переключалось между светлой и тёмной темой. Слушай событие themeChanged.
3. Для навигации внутри приложения используй BackButton Telegram, для главного действия — нижнюю кнопку.
4. При запуске отправляй сырую строку WebApp.initData (не initDataUnsafe) POST-запросом на /api/telegram/auth.
Ограничения: вне Telegram всё работает ровно как раньше. На фронтенде никаких новых зависимостей,
кроме официального скрипта.
Готово, когда: по ссылке t.me приложение открывается в цветах Telegram, а в обычном браузере ничего не изменилось.
```

### 3. Проверь initData на сервере (40 минут)

Алгоритм — прямо из документации Telegram:

1. Разбери `initData` как параметры URL. Вынь оттуда `hash`.
2. **Все** оставшиеся пары `ключ=значение` отсортируй по ключу (новые клиенты присылают ещё поле `signature` — оно
   остаётся) и склей через `\n` — это **data-check-string**.
3. `secret_key = HMAC_SHA256(ключ = "WebAppData", сообщение = токен_бота)`.
4. `expected = hex(HMAC_SHA256(ключ = secret_key, сообщение = data_check_string))`.
5. Сравни `expected` с `hash` за постоянное время. И отклоняй строку, если `auth_date` старше, скажем, суток.

```text
Цель: добавить POST /api/telegram/auth, который проверяет initData от Telegram Mini App и логинит пользователя.
Реализуй официальный алгоритм точно: HMAC с ключом WebAppData, отсортированная data-check-string,
сравнение за постоянное время, отказ, если auth_date старше 24 часов. На Workers — через Web Crypto;
если подходит стек, возьми поддерживаемую библиотеку (например, @telegram-apps/init-data-node
или safe_parse_webapp_init_data из aiogram для Python).
Токен бота берётся из секрета окружения и никогда не приходит с клиента.
При успехе: найди или создай пользователя по telegram_id, открой нашу обычную сессию, верни пользователя.
При ошибке: 401 с понятным сообщением. Логируй причину отказа, токен не логируй никогда.
Тесты: валидная initData (подписанная в тесте фейковым токеном), initData с подменённым полем user,
просроченная initData. Все три должны отрабатывать правильно.
Готово, когда: тесты зелёные, а внутри Telegram приложение здоровается со мной по имени из ответа сервера.
```

Теперь атакуй себя сам. Открой приложение в Telegram, скопируй `initData`, которую шлёт фронтенд (в режиме
разработки один раз выведи её в лог), поменяй одну букву в имени и отправь через curl:

```bash
curl -i -X POST https://<твоё-приложение>/api/telegram/auth \
  -H "Content-Type: application/json" \
  -d '{"initData":"<подделанная строка>"}'
```

Должен прийти `401`. Пришёл `200` — значит, проверка ничего не проверяет. (На Windows запускай это в Git Bash:
PowerShell по-своему понимает кавычки и переносы строк. Или просто попроси агента отправить запрос за тебя.)

> **Если застрял:** самая частая ошибка — собирать data-check-string из уже раскодированного JSON в другом порядке или
> случайно включить в неё `hash`. Вторая по частоте — использовать токен бота напрямую как ключ HMAC, без шага с
> `WebAppData`. Дай агенту свою функцию и кусок документации и попроси сравнить построчно. Внутри Telegram белый
> экран? Открой Mini App в Telegram Desktop с включённой отладкой WebView (раздел «Debug Mode» в документации Mini
> Apps) — получишь DevTools.

> **Про деньги:** если продаёшь внутри Mini App **цифровые** товары или функции, Telegram требует оплату в **Telegram
> Stars** (валюта `XTR`): бот создаёт ссылку на счёт, приложение вызывает `WebApp.openInvoice()`. Физические товары
> и услуги (например, запись к мастеру) можно принимать через обычных платёжных провайдеров вроде ЮKassa — проверь,
> какие доступны в твоей стране. Правила меняются, так что перед расчётом цен прочитай страницу про Stars в ресурсах.

Для доказательства по третьей задаче напиши 3–5 предложений: какие поля проверяешь, где лежит токен, что происходит
при ошибке и чем закончился тест с подделанной строкой.

## Мини-тест

1. Фронтенд присылает `{"userId": 777}` из `initDataUnsafe`. Можно серверу этим пользоваться?
2. Зачем в проверке `auth_date`?
3. Может, проверять `initData` прямо в браузере, чтобы не гонять запрос на сервер?
4. Mini App вызывает Claude API прямо с фронтенда твоим ключом. Что не так?

<details><summary>Ответы</summary>

1. Нет. `initDataUnsafe` — неподписанные данные для удобства, подделать их может кто угодно. Доверяй только тому, что
   сервер достал из проверенной `initData`.
2. Чтобы защититься от повтора: валидная строка, скопированная месяц назад, сегодня никого залогинить не должна.
3. Нет. Для проверки нужен токен бота; положить его в браузер — значит подарить бота всем желающим.
4. Ключ видит любой пользователь. Все вызовы модели идут через твой сервер, и он сначала проверяет сессию.

</details>
