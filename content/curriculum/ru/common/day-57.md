Восемь недель подряд ты делаешь вещи. С сегодняшнего дня — ещё и так, чтобы за них было удобно *заплатить*.
Начинается это с одной ссылки, которую можно кинуть куда угодно: портфолио, которое срабатывает за 30 секунд. Бета
финального проекта тем временем крутится в фоне.

## На что смотрит заказчик за 30 секунд

Занятой человек открывает твою ссылку между двумя созвонами. По порядку он проверяет:

1. **Что ты делаешь и для кого?** Одно предложение наверху. «Делаю Telegram-ботов и ИИ-инструменты для малого
   бизнеса» работает лучше, чем «Привет, я Саша, увлечённый креатор».
2. **Хороша ли первая работа?** Смотрят одну, максимум две. Самое сильное — первым.
3. **Это всё настоящее?** Живая ссылка, которую можно нажать, ролик, который играет прямо на странице. Одни
   скриншоты выглядят как макет.
4. **Как с тобой связаться?** Почта или Telegram — видно сразу, а не где-то в самом низу.

Что пролистывают: полоски навыков («JavaScript 80%»), длинные рассказы о себе, перечни инструментов. Покажи
результат, а инструменты упомяни одной строкой у каждой работы. И честно скажи, что работаешь с ИИ-агентами:
умение толково ими управлять — это и есть навык, который ты продаёшь.

## Шаг 1. Выбери и подготовь 3–5 работ (25 минут)

Начни с трёх «зёрен» 35-го дня, добавь работу для заказчика с 41-го и бету финального проекта. Для каждой запиши:
название, результат одной строкой («вдвое меньше переписки о записи для студии на двух мастеров»), твоя роль, на чём
сделано, ссылка.

**Приложения:** у каждой работы — живой адрес, скриншот и, в идеале, клип главного сценария на 5–8 секунд. Чистые
скриншоты агент снимет Playwright'ом (один раз `npx playwright install chromium`, потом
`npx playwright screenshot --viewport-size=1280,800 https://твоё-приложение.example.com shot.png`).

**Видео:** здесь ролик и есть товар, поэтому он должен заиграть мгновенно. Сделай лёгкое беззвучное превью и
кадр-обложку для каждой работы, а полную версию дай ссылкой:

```bash
# кадр-обложка на третьей секунде
ffmpeg -ss 3 -i explainer.mp4 -frames:v 1 -q:v 3 explainer.jpg
# беззвучное превью на 8 секунд, 720p, для веба
ffmpeg -ss 0 -t 8 -i explainer.mp4 -vf "scale=-2:720" -c:v libx264 -pix_fmt yuv420p -crf 28 -preset slow -an -movflags +faststart explainer-preview.mp4
```

Превью держи в пределах ~5 МБ. GitHub не примет файл больше 100 МБ, а Cloudflare Pages — больше 25 МиБ, так что
полные версии живут на видеоплатформе. Если твои заказчики в России, YouTube у них может грузиться плохо — продублируй
ролик на VK Видео или Rutube и вставь ссылку на ту площадку, где его точно посмотрят.

## Шаг 2. Собери с агентом (30 минут)

Создай новый репозиторий `portfolio` и вставь:

```text
Цель: одностраничное портфолио, по которому заказчик за 30 секунд понимает, что я делаю и как меня нанять.
Контекст: я новичок и делаю проекты с ИИ-агентами (мой трек — приложения или видео, см. работы ниже).
Работы храни в projects.json, чтобы новые можно было добавлять, не трогая вёрстку.
Работы: (вставь 3–5 работ: название, результат одной строкой, роль, на чём сделано, ссылка, картинка или превью)
Ограничения: статический сайт (чистый HTML/CSS/JS или Vite — выбери и объясни одной строкой); сначала мобильная версия; светлая и тёмная тема по системной настройке; самая сильная работа первой и крупнее; видеопревью играют без звука, по кругу, с обложкой; контакты (почта + Telegram) в первом экране и в подвале; нормальные title, meta description и картинка для превью ссылки (Open Graph); весь текст на русском; быстрая загрузка — никаких тяжёлых фреймворков ради одной страницы.
Готово, когда: сайт запускается локально, нормально выглядит при ширине 390 и 1280 пикселей, и ты объяснил, как его задеплоить.
```

Смотри на результат в узком окне, а не только на большом экране. Правки проси скриншотами и фразами «что и где» —
как в первый день со страницей-обещанием.

## Шаг 3. Задеплой (15 минут)

Выбери один вариант — агент умеет работать с любым:

- **GitHub Pages** — то же, что на втором дне: Settings → Pages → публикация из `main`.
- **Cloudflare** или **Vercel** — подключаешь репозиторий, каждый пуш выкладывается сам. Удобно, если позже
  захочешь свой домен. Если какой-то сервис недоступен в твоей стране, GitHub Pages работает почти везде.

```bash
git add -A && git commit -m "Portfolio v1" && git push
```

> **Если застрял:** 404 на GitHub Pages почти всегда значит, что в Settings → Pages выбрана не та ветка или папка,
> либо публикуется не та папка сборки (например, нужна `dist`). Вставь агенту точные настройки Pages и дерево
> папок и попроси проверить оба места.

## Шаг 4. Два отзыва (20 минут)

Отправь ссылку двоим: тому, кто сам что-то делает (кому-то из FlowLeaf), и тому, кто мог бы стать заказчиком
(владелице кофейни, блогеру, знакомому менеджеру). Спроси ровно так:

```text
Открой, пожалуйста, на 30 секунд и скажи: чем я занимаюсь, какая работа запомнилась и понятно ли, как со мной связаться? Можно жёстко.
```

Поменяй хотя бы одну вещь по их словам и запушь снова.

## Готово, когда…

- [ ] Ты знаешь, что заказчик проверяет за 30 секунд.
- [ ] Портфолио онлайн, в нём 3–5 работ, ссылка вставлена.
- [ ] Оба отзыва вставлены по строке, и рядом — что изменено.

**Завтра:** превращаешь лучшую работу в кейс и монтируешь демо на 60–90 секунд.
