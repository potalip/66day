Агент живёт в терминале, а значит, и тебе там проводить немало времени. Хорошая новость: хватит примерно дюжины
команд, и большую часть из них наберёт агент. Сегодня ты научишься понимать, что он делает, поставишь три
инструмента, на которых держатся все следующие дни, и получишь первую полезную программу.

## Дюжина команд

Терминал всегда «стоит» в какой-то папке — это как окно проводника, только без картинок.

| Команда | Что делает |
|---|---|
| `pwd` | Где я? Показывает текущую папку |
| `ls` | Что тут лежит? Список файлов (`ls -la` покажет и скрытые; в PowerShell — `ls -Force`) |
| `cd папка` / `cd ..` / `cd ~` | Зайти в папку / подняться на уровень выше / домой |
| `mkdir имя` | Создать папку |
| `cp a b` / `mv a b` | Скопировать / переместить или переименовать файл |
| `rm файл` | Удалить файл. **Корзины нет.** Перечитай, прежде чем жать Enter |
| `cat файл` | Вывести содержимое файла |
| `clear` | Очистить экран (не файлы!) |
| **Tab** | Дописать имя файла или папки — минус опечатки |
| **↑** | Повторить предыдущую команду |
| **Ctrl+C** | Остановить то, что сейчас работает |

Всё это работает и в PowerShell на Windows. Потрать пять минут на прогулку по папкам: `cd ~`, `ls`,
`cd 66-day-promise`, `cat index.html`, `cd ..`. Вот и весь фокус.

## Шаг 1. Ставим Node.js, Python и ffmpeg (25 минут)

**Node.js** запускает JavaScript вне браузера: веб-приложения, боты. **Python** — второй большой язык: скрипты,
данные, видео. **ffmpeg** — швейцарский нож для видео и звука. Найди свою систему:

```bash
# macOS (Homebrew уже стоит со второго дня)
brew install node python ffmpeg
```

```powershell
# Windows — по одной строке, потом закрой и снова открой терминал
winget install OpenJS.NodeJS.LTS
winget install Python.Python.3.14
winget install Gyan.FFmpeg
```

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install python3 python3-pip python3-venv ffmpeg
# Node в apt часто устаревший: выполни строку установки nvm с nodejs.org/en/download,
# закрой и снова открой терминал, затем
nvm install --lts
```

Версии меняются быстро. На Windows команда `winget search Python.Python` покажет актуальные 3.x: если 3.14 уже
не самая новая, бери самую свежую. Теперь проверь все три:

```bash
node --version
python3 --version      # на Windows: python --version
ffmpeg -version        # с одним дефисом; хватит первой строки
```

> **Если застрял:** «not recognized» или «command not found» сразу после установки? Открой новое окно терминала —
> старое ещё не знает о новых программах. Если на Windows `python` открывает Microsoft Store, отключи пункты Python
> в «Параметры → Приложения → Дополнительные параметры → Псевдонимы выполнения приложений» и перезапусти терминал.
> С остальным просто: копируй ошибку агенту.

**Доказательство:** вставь три строки с версиями.

## Шаг 2. Первая консольная утилита (30 минут)

**Консольная утилита** (CLI) — программа, которую запускают, набирая её имя. Наша разложит захламлённую папку
«Загрузки» по типам файлов. Перемещать файлы рискованно, поэтому сначала будет **пробный прогон** (dry run):
утилита только *показывает*, что сделала бы. Создай для неё папку:

```bash
cd ~
mkdir tidy
cd tidy
claude
```

```text
Цель: небольшая консольная утилита на Python, tidy.py, которая раскладывает файлы в папке по подпапкам: Картинки, Документы, Видео, Аудио, Архивы, Прочее.

Контекст: я новичок, Python 3 установлен. Определи, какая у меня операционная система, и подскажи точную команду запуска.

Ограничения:
- Только стандартная библиотека, один файл.
- Запуск: python tidy.py <папка> (раскрывай ~ в пути). По умолчанию — ПРОБНЫЙ ПРОГОН: утилита выводит таблицу «файл -> куда» и количество по категориям и ничего не перемещает.
- Перемещает файлы только с флагом --apply.
- Только файлы верхнего уровня; подпапки не трогать, ничего не удалять, ничего не перезаписывать (если имя занято, добавляй « (2)»).
- Сначала создай тестовую папку sample с 12 пустыми файлами разных типов и покажи работу утилиты на ней.

Готово, когда: ты показал пробный прогон на sample, потом --apply на sample и объяснил код в пяти коротких пунктах.
```

Посмотри, как утилита отработала на `sample`. Если всё логично, сделай пробный прогон на настоящих «Загрузках».
В терминале эта папка называется `Downloads` (на Windows вместо `python3` пиши `python`):

```bash
python3 tidy.py ~/Downloads
```

На Mac может выскочить окно с вопросом, можно ли Терминалу заходить в «Загрузки», — разреши, иначе утилита увидит
пустую папку. Прочитай план. Устраивает — добавь `--apply`. Сомневаешься — не добавляй: пробный прогон без
применения — тоже победа.

> **Совет:** «сначала пробный прогон» — привычка на всю жизнь. Если скрипт от агента что-то перемещает, удаляет или
> отправляет, проси у агента режим dry run.

**Доказательство:** скриншот вывода пробного прогона.

## Мини-тест

Что делает каждая команда?

1. `cd ..`
2. `mkdir музыка`, а потом `cd музыка`
3. `rm -r старый-проект`
4. `python3 tidy.py ~/Downloads --apply`

> **Ответы:**
>
> 1. Переходит на одну папку выше.
> 2. Создаёт папку `музыка` и заходит в неё.
> 3. Удаляет папку `старый-проект` со всем содержимым — навсегда. Перед такой командой сделай паузу.
> 4. Запускает утилиту на «Загрузках» по-настоящему: файлы будут перемещены.
