Сейчас твоё приложение живёт во вкладке браузера, где-то между прогнозом погоды и сорока открытыми статьями с Хабра.
Пользователь его просто теряет. Сегодня у него появится иконка на телефоне, запуск на весь экран и спокойное
«нет сети» вместо пустой страницы, когда метро уходит в туннель. Без модерации в App Store, без $99 в год — три
файла и час времени.

## Что такое PWA на самом деле

**Progressive Web App** — это твой обычный сайт плюс три вещи:

1. **Манифест** (`manifest.webmanifest`) — маленький JSON, где написано имя приложения, иконки, цвета и как его
   открывать. `"display": "standalone"` значит «без адресной строки, как настоящее приложение».
2. **Service worker** — скрипт, который браузер запускает в фоне, между приложением и сетью. Представь вахтёра на
   входе: каждый запрос проходит мимо него, и если сети нет, он выдаёт ответ из своего шкафчика — кэша.
3. **HTTPS** — он у тебя уже есть, приложение ведь задеплоено.

Браузер видит манифест, нормальную иконку и HTTPS — и предлагает «Установить приложение». А service worker отвечает за
работу без сети.

> **Важно: iPhone живёт по своим правилам.** Автоматического предложения установить там нет. Пользователь сам жмёт
> «Поделиться» → «На экран „Домой“». Пуш-уведомления на iOS работают только у приложений, добавленных так (iOS 16.4
> и новее), а Safari может стереть кэш PWA, если им долго не пользовались. Поэтому сделай маленькую подсказку «Как
> установить на iPhone» и никогда не храни важное только в офлайн-кэше.

## Что значит «базовый офлайн»

Не пытайся сделать всё приложение офлайновым: это уже синхронизация данных и неделя работы. Сегодняшняя планка:

- **Оболочка приложения** (HTML, CSS, JS, иконки, шрифты) лежит в кэше и открывается мгновенно даже без сети.
- **Запросы к API** идут сначала в сеть; если сети нет — человек видит понятное сообщение, а не белый экран.
- По желанию: **последние данные**, которые человек видел (например, список записей), показываются только для
  чтения, с плашкой «Нет подключения».

## Шаг за шагом

### 1. Прочитай и реши (10 минут)

Пролистай страницу MDN про PWA из ресурсов. Потом придумай текст офлайн-экрана — по-человечески. Например, для
приложения записи к мастеру: «Нет интернета. Вот твои ближайшие записи — новую запись можно будет сделать, когда
связь вернётся».

### 2. Сделай приложение устанавливаемым (35 минут)

Если проект на Vite, агент, скорее всего, возьмёт `vite-plugin-pwa`: он сам сгенерирует манифест и service worker на
Workbox. Хороший выбор. Ставь задачу:

```text
Цель: сделать главное приложение устанавливаемым PWA с базовой работой без сети.
Контекст: приложение на Vite, задеплоено на <твой адрес>; API живёт под /api.
Сделай:
1. Манифест: name, short_name (до 12 символов), start_url "/", display "standalone",
   theme_color и background_color из наших дизайн-токенов, иконки 192x192 и 512x512 и отдельную
   maskable-иконку 512, сгенерированные из логотипа (исходник положи в /public).
2. Service worker (vite-plugin-pwa с Workbox подойдёт): прекэш оболочки приложения; для /api стратегия
   «сначала сеть» с таймаутом 3 секунды; никогда не кэшируй POST-запросы и ответы с авторизацией.
3. Офлайн-заглушка: если страница или запрос к API падает без сети, показывай понятную плашку или страницу
   на всех языках приложения, а не пустой экран.
4. Кнопка «Установить приложение» через beforeinstallprompt там, где он поддерживается; в Safari на iOS вместо
   неё короткая подсказка: «Поделиться» → «На экран „Домой“».
5. Обновления: после нового деплоя показывай «Доступна новая версия — обновить», а не старый код навечно.
Ограничения: существующие функции не трогай, сборка должна проходить.
Готово, когда: в Chrome DevTools > Application манифест без ошибок и service worker активен,
а в режиме Offline приложение открывается и показывает офлайн-сообщение.
```

Проверь сам:

```bash
npm run build && npm run preview
```

Открой в Chrome, нажми F12 → **Application** → **Manifest** (без красных ошибок) → **Service workers** (статус
activated). Во вкладке **Network** выбери режим **Offline** и обнови страницу. Приложение должно открыться.

> **Если застрял:** «Service worker не регистрируется» почти всегда значит, что ты открыл сайт по `http://` не на
> localhost, или файл воркера лежит в подпапке и не может управлять корнем `/`. Скопируй агенту точный текст ошибки
> из DevTools. Если упорно показывается старая версия — поставь галочку **Update on reload** в панели Service workers.
> У твоих пользователей такой галочки нет, поэтому пункт 5 в промпте не формальность.

### 3. Установи на настоящий телефон (10 минут)

Задеплой и открой живой адрес на телефоне. Android и Chrome: меню → «Установить приложение» (или твоя кнопка).
iPhone и Safari: «Поделиться» → «На экран „Домой“». Запусти с иконки. Включи авиарежим и открой ещё раз.

Сделай скриншот рабочего стола, где видна иконка, — это твоё доказательство. Бонус: второй скриншот офлайн-экрана в
авиарежиме.

## Мини-тест

1. Может ли PWA присылать пуш-уведомления на iPhone?
2. Без сети приложение открылось, но список записей пустой. Service worker сломан?
3. Можно ли выложить PWA в Google Play?
4. Может ли PWA читать контакты и СМС, как нативное приложение?

<details><summary>Ответы</summary>

1. Да, на iOS 16.4 и новее, но только если его добавили на экран «Домой» и человек разрешил уведомления. В обычной
   вкладке Safari — нет.
2. Скорее всего, нет. Ты закэшировал оболочку, а не данные. Кэшировать ответы API (или хранить последний результат в
   IndexedDB) — отдельное решение.
3. Да, если упаковать его как Trusted Web Activity (это делают Bubblewrap или PWABuilder). App Store к тонким
   веб-обёрткам гораздо строже.
4. Нет. Веб-приложению доступны камера, микрофон, геолокация, уведомления и файлы — с разрешения, — но не контакты,
   СМС и глубокие системные функции. Некоторые API (Bluetooth, USB) работают только в браузерах на Chromium.

</details>

## Подумай: магазин, PWA или бот?

У тебя теперь три способа попасть в телефон: PWA, твой Telegram-бот и (теоретически) нативное приложение. Напиши
4–6 предложений: что из этого **твои** пользователи реально будут открывать каждый день и почему? Подумай, кто они.
Мастеру маникюра, который смотрит записи между клиентами, нужна иконка. Компания друзей, которая делит счёт за
шашлыки, и так живёт в чате — им бот. А шагомеру, которому нужен доступ к датчикам в фоне, без нативного приложения
не обойтись.
