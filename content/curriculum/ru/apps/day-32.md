День, когда кто-то впервые платит за сделанное тобой, — особенный. Сегодня ты строишь весь денежный путь в
**тестовом режиме**: без настоящих карт и денег, но с тем самым кодом, что потом пойдёт в продакшен. К вечеру в
приложении появится тариф «Про», который включается только настоящей (тестовой) оплатой.

## Как на самом деле проходит платёж

Участников пять: твой **фронтенд**, твой **сервер**, **платёжный сервис**, **банк** покупателя и **уведомление**
(вебхук) от платёжного сервиса к тебе. Возьмём ЮKassa — её платёжная страница принимает карты, СБП и кошельки, так
что номера карт до твоего приложения вообще не доходят:

1. Пользователь жмёт «Подключить Про». Твой **сервер** создаёт платёж через API ЮKassa (сумма, описание,
   `metadata` с id пользователя, `return_url`) и получает ссылку на оплату.
2. Браузер уходит на страницу ЮKassa. Пользователь платит — или нет.
3. ЮKassa возвращает браузер на `return_url`. **Это ничего не доказывает.** Этот адрес может открыть кто угодно.
4. Отдельно, от сервера к серверу, приходит **HTTP-уведомление** на `/api/payments/webhook` с событием
   `payment.succeeded` или `payment.canceled`.
5. Твой сервер **не верит телу уведомления на слово**: берёт id платежа и сам запрашивает его через API ЮKassa.
   Только если там `status: succeeded` и метаданные совпадают, ставит в базе `plan = 'pro'`.

Страница возврата просто пишет «Спасибо! Включаем…» и опрашивает твой API, пока база не скажет «Про».

### Что выбрать тебе

- **Веб-приложение, ты в России** — ЮKassa. Тестовый магазин создаётся в личном кабинете бесплатно; для боевого
  понадобится ИП, ООО или статус самозанятого.
- **Цифровая функция в Telegram-боте** — **Telegram Stars**: правила Telegram требуют оплачивать цифровые товары в
  ботах именно звёздами, и это работает из любой страны.
- **Ты в ЕС, Израиле, Сербии или другой стране, где доступен Stripe**, — Stripe Checkout: схема та же, подпись
  уведомления проверяется по секрету.

Выбери один путь на сегодня. Ниже — ЮKassa подробно и Stars коротко.

## Шаг за шагом

### 1. Подготовка (15 мин)

ЮKassa: зарегистрируйся, создай **тестовый магазин**, возьми `shopId` и тестовый секретный ключ, положи в `.dev.vars`
/ `.env` как `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. В настройках магазина укажи адрес для HTTP-уведомлений.
Локально нужен публичный адрес — подними туннель (`cloudflared tunnel --url http://localhost:8787` или ngrok)
или сразу проверяй на задеплоенной версии.

### 2. Оплата → уведомление → «Про» (55 мин)

```text
Цель: пользователь покупает «Про» через ЮKassa (тестовый магазин); «Про» включается только после проверенного уведомления.
Контекст: наше приложение (React + Vite, API на Cloudflare Workers или Node, база D1, вход из дня 24).
Ключи в YOOKASSA_SHOP_ID и YOOKASSA_SECRET_KEY, цена — в переменной PRO_PRICE_RUB.
Ограничения:
- POST /api/billing/checkout (только для вошедших) создаёт платёж через POST /v3/payments: Basic-авторизация,
  заголовок Idempotence-Key (новый UUID на каждую попытку), capture: true, confirmation type redirect,
  metadata.user_id. Сумму и пользователя берём на сервере, никогда из браузера. Возвращаем confirmation_url.
- POST /api/payments/webhook: из тела берём только id платежа, затем GET /v3/payments/{id} через API; включаем «Про»
  только при status succeeded и совпадении суммы. На всё остальное — ответ 200 без изменений.
- Таблица processed_payments (payment_id UNIQUE): если платёж уже обработан — 200 и ничего не делаем.
- Страница возврата опрашивает GET /api/me, пока plan не станет 'pro'. Платная функция проверяет тариф на СЕРВЕРЕ.
- Нет ключей — показываем «Оплата не настроена», ничего не падает.
Готово, когда: тестовая оплата включает «Про», а платная функция отвечает 403 бесплатному пользователю даже через curl.
```

Номер тестовой карты возьми в разделе «Тестирование» документации ЮKassa. Оплати, посмотри, как приходит уведомление
и твой сервер отвечает `200`. Сделай скриншот: включённая функция «Про» рядом с тестовым платежом в личном кабинете
ЮKassa (или с логом сервера). Это задание 2.

**Вариант со Stars для бота:**

```text
Цель: команда /pro в боте продаёт «Про» за Telegram Stars.
Ограничения: sendInvoice с currency "XTR" и пустым provider_token; на pre_checkout_query отвечаем ok за пару секунд
(Telegram ждёт не больше 10); «Про» включаем только по сообщению successful_payment;
telegram_payment_charge_id сохраняем с UNIQUE и используем как ключ идемпотентности;
команда /refund_test для владельца возвращает звёзды через refundStarPayment.
Готово, когда: покупка за 1 звезду включает «Про», а возврат его выключает.
```

> **Если застрял:** уведомления не приходят — проверь, что адрес публичный, по HTTPS, и указан в настройках именно
> тестового магазина. Ответ `401` от API ЮKassa — перепутаны shopId и ключ или взяты ключи боевого магазина. Платёж
> застрял в `waiting_for_capture` — ты создал его без `capture: true`, и он ждёт ручного подтверждения.

### 3. Несчастливые сценарии (35 мин)

Настоящие деньги — это в основном пограничные случаи. Сделай каждый скучным:

- **Отмена**: пользователь закрыл страницу оплаты или нажал «назад». Он на `return_url`, но статус не `succeeded` —
  спокойное сообщение, тариф бесплатный, без ошибок.
- **Отказ банка**: возьми из документации тестовую карту с отказом. Придёт `payment.canceled` — в базе ничего не меняется.
- **Повторное уведомление**: ЮKassa повторяет уведомления, если не получила `200`. Отправь то же уведомление ещё раз
  сам (`curl` с тем же телом) — таблица `processed_payments` должна сделать второе пустым.
- **Уведомление раньше возврата** (или сильно позже): страница опрашивает API, так что работают оба порядка.
- **Возврат денег** (бонус): обработай `refund.succeeded` и верни тариф на бесплатный.

Для задания 3 опиши, как ведёт себя приложение в каждом из четырёх случаев и какая строка кода защищает от дубля.

> **Безопасность:** не пиши полные уведомления с почтами покупателей в общие логи, не клади секретный ключ во фронтенд,
> а боевые ключи включай только в продакшене и только после ревью. Чеки по 54-ФЗ ЮKassa умеет формировать сама —
> разберёшься, когда дойдёт до боевого магазина.

## Мини-тест

1. Пользователь попал на `/success?payment=…`. Можно включать «Про»?
2. Почему сумму выбирает сервер, а не браузер?
3. Уведомление пришло дважды. Что спасает от двойного включения и двух писем?
4. Твой вебхук час отвечает `500`. Что сделает платёжный сервис?

<details><summary>Ответы</summary>

1. Нет. Этот адрес может открыть кто угодно. Включаем только по проверенному уведомлению (или после запроса статуса платежа через API на сервере).
2. Всё из браузера можно подменить. Иначе «Про» купят за рубль.
3. id платежа (или события), сохранённый с ограничением уникальности, и пропуск уже обработанных.
4. Будет повторять уведомление ещё какое-то время (точный срок — в актуальной документации), поэтому обработчик обязан быть идемпотентным.

</details>
