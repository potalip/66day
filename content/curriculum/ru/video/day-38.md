Один отличный ролик — лотерейный билет. Рубрика — это канал. Когда зритель знает, что получит, — ту же длину, ту же форму,
тот же маленький ритуал в конце, — он возвращается за этим, площадка понимает, кому показывать, а ты с каждым выпуском
делаешь быстрее. И тебе, в отличие от большинства авторов, рубрика обходится дёшево: это один шаблон и JSON-файл, где
каждая строка — выпуск.

## Из чего состоит формат

**Формат** — это всё, что остаётся неизменным, чтобы меняться мог только смысл. Запиши его на одной странице, как
«библию формата»:

- **Название и обещание** одной строкой: «Как это устроено — обычная вещь, которую ты трогаешь каждый день, за
  40 секунд».
- **Жёсткая структура с таймингами:** холодное начало с хуком (3 с) → заставка рубрики (1 с) → объяснение в три шага
  (26 с) → «а ты знал?» (7 с) → фирменное прощание (3 с).
- **Повторяющиеся элементы:** одна и та же заставка, одна и та же финальная фраза, номер выпуска в углу, свой цвет у
  каждого блока. Именно по ним рубрику узнают в ленте раньше, чем прочитают хоть слово.
- **Что меняется:** тема, факты, картинки, финальный поворот.
- **Граница:** чего рубрика не делает никогда (никаких топов, никаких мнений, никаких тем без источника).

Хорошие форматы для роликов из кода: «X за 40 секунд», «один график в неделю», «миф или правда», «слово дня»,
«этот день в истории», «термин из твоей профессии». Лучший формат скучно описывать и интересно смотреть.

Прежде чем строить, ответь на один вопрос: **можешь назвать 20 выпусков прямо сейчас?** Если застрял на седьмом,
формат слишком узкий.

## Шаг за шагом

### 1. Напиши series.json

```json
{
  "series": {
    "name": "Как это устроено",
    "promise": "Обычная вещь, которую ты трогаешь каждый день, за 40 секунд.",
    "language": "ru",
    "brand": "brand/brand.json",
    "structure": [
      { "segment": "cold_open", "seconds": 3 },
      { "segment": "sting", "seconds": 1 },
      { "segment": "explain", "seconds": 26, "beats": 3 },
      { "segment": "did_you_know", "seconds": 7 },
      { "segment": "signoff", "seconds": 3, "line": "Вещи простые, если знать, как они устроены. До пятницы." }
    ]
  },
  "episodes": [
    { "n": 1, "topic": "ключ-таблетка от домофона", "angle": "внутри просто чип с уникальным номером", "sources": [] },
    { "n": 2, "topic": "турникет в метро", "angle": "карта питается от поля турникета, батарейки в ней нет", "sources": [] },
    { "n": 3, "topic": "штрихкод на молоке", "angle": "полоски — это 13 цифр для машины", "sources": [] }
  ]
}
```

Бери, конечно, свою идею рубрики — лучше всего про то, о чём твой канал. Заполни `sources` хотя бы одной настоящей
ссылкой на выпуск, которую ты сам открыл и прочитал, — рендер откажется собирать выпуск с пустым списком.

### 2. Научи пайплайн формату

```text
Цель: рендерить всю рубрику из series.json моим пайплайном make-video.
Контекст: пайплайн с 33–34-го дня, этап раскадровки с 31-го, фирменный стиль с 32-го. Сначала прочитай их.
Сделай:
- Компоненты SeriesSting и EpisodeBadge (номер выпуска, название рубрики) на моём фирменном стиле.
- Этап storyboard принимает --series series.json --episode N: модель обязана заполнить жёсткую структуру (названия блоков и секунды из series.json), раскрыть angle выпуска и утверждать только то, что можно связать с источниками. Финальная фраза вставляется дословно, модель её никогда не переписывает.
- Откажись рендерить выпуск с пустым sources, с понятным сообщением.
- render_series.py рендерит все выпуски (или --only 2), каждый в runs/<series-slug>/ep-0N/, используя кэш. Общие ресурсы (заставка, музыкальная подложка, стиль) рендерятся один раз.
- В конце таблица: выпуск, длительность, время рендера, стоимость.
Готово, когда: python render_series.py series.json выдаёт три готовых выпуска, которые выглядят как одна рубрика.
```

Посмотри все три подряд. Похоже на одну передачу? Если второй выпуск выбивается, найди причину: обычно модель растянула
блок или у одного выпуска другой вид визуала. Чини шаблон или промпт, а не выпуск. Загрузи один выпуск.

> **Если застрял:** если модель игнорирует тайминги, проверяй раскадровку по series.json кодом и один раз отправляй ей
> ошибки (тот же приём, что на 31-й день). Если модель упорно «улучшает» финальную фразу, вообще не проси её об этом —
> вставляй фразу кодом после генерации.

> **Совет:** добавь в series.json ещё три-четыре будущих выпуска как черновики. Идеи приходят пачками, а рендерить
> можно потом.

### 3. Опубликуй первый выпуск

Прогони первый выпуск через этап публикации с 36-го дня, с названием рубрики и номером в заголовке («Как это устроено
№1: что внутри таблетки от домофона»). Опубликуй открыто там, где твоя аудитория: VK Клипы, Telegram-канал, Shorts.
Вставь ссылку.

### 4. Потянешь 50?

Честно, в 4–5 предложениях: сколько занял один выпуск от начала до конца, вместе с проверкой фактов? Сколько стоил?
Что сломается первым на двадцатом выпуске — идеи, источники, терпение, бюджет, усталость формата? Какое одно изменение
сделает 50 выпусков реальными?

## Готово, когда…

- [ ] Ты описываешь формат одной строкой и можешь назвать минимум 20 выпусков.
- [ ] Из одного `series.json` отрендерены три выпуска, один загружен.
- [ ] Первый выпуск опубликован, ссылка вставлена.
- [ ] Написан честный разбор «потяну ли 50 выпусков».

Завтра — чужой продукт. Промо и демо-ролики, за которые бизнес реально платит.
