Вчера ты отправил первые пять откликов. Если хоть один ответит «да», новый проект придётся начинать быстро — а скучные
части ты уже собирал раза три-четыре: вход, база, аккуратный вызов модели, оплата. Сегодня ты перестаёшь их
пересобирать. **Стартовый шаблон** — твой собственный готовый фундамент: склонировал, переименовал, заполнил `.env`,
задеплоил — и через 15 минут занимаешься задачей заказчика, а не настройкой авторизации на третий день.

## Что внутрь, а что нет

Стартовый шаблон — это кухня с наточенными ножами, а не замороженный ужин. В нём то, что нужно *любому* проекту,
собранное и проверенное, и ничего про идею твоего финального проекта.

**Внутрь:**

- **Авторизация** — регистрация, вход, выход, защищённый маршрут, проверка сессии на сервере.
- **База** — одна миграция с таблицей `users` и одной таблицей-примером, плюс типизированный помощник для запросов.
- **ИИ** — одна серверная функция вызова модели: тайм-ауты, повторы, лимит токенов, лимит запросов и заготовленный
  ответ, если ключа (`ANTHROPIC_API_KEY` или ключа твоего провайдера, хоть GigaChat, хоть YandexGPT) нет.
- **Оплата** — платёж в **тестовом режиме** и обработчик уведомлений, который проверяет подлинность запроса и
  отмечает пользователя как оплатившего. Для России — ЮKassa (у неё есть тестовый магазин), для ботов и Mini Apps —
  Telegram Stars, для зарубежных клиентов — Stripe, если он доступен в твоей стране.
- **Скучные обязательные вещи** — `.env.example`, README с запуском в 3 команды, `CLAUDE.md`/`AGENTS.md` со
  структурой и правилами, один тест на Vitest, один дымовой тест на Playwright, светлая и тёмная тема, CI, который
  гоняет сборку.

**Не внутрь:** экраны, промпты, данные и бренд финального проекта, а также всё, где есть настоящие ключи.

> **Совет:** главное оружие — файл памяти проекта. Хороший `CLAUDE.md` в шаблоне означает, что каждая будущая сессия
> агента сразу знает твой стек, структуру папок и правила («ключи никогда не попадают на клиент»).

## Шаг за шагом

### 1. Вынеси шаблон (50 мин)

Работай в **новом** репозитории, а не в финальном проекте. Открой агента так, чтобы он видел обе папки, и дай задачу:

```text
Цель: сделать переиспользуемый стартовый шаблон в ./starter на основе моего проекта в ./capstone.
Оставь (обобщив, с нейтральными названиями): авторизацию, слой базы данных и первую миграцию, помощник вызова ИИ
с тайм-аутами, повторами, лимитом запросов и фикстурой, оплату в тестовом режиме [ЮKassa / Telegram Stars / Stripe]
с проверкой уведомлений, светлую и тёмную темы, один тест на Vitest, один тест на Playwright,
workflow в GitHub Actions: установка + сборка + тесты.
Убери: все экраны, промпты, таблицы, тексты и картинки, относящиеся к финальному проекту. Главная страница —
крошечное демо: вход → одна форма → ответ ИИ → кнопка «Оплатить», открывающая тестовую оплату.
Добавь: .env.example со всеми переменными и комментарием к каждой; README с разделами «Запуск в 3 команды»
и «Как задеплоить»; CLAUDE.md и AGENTS.md про стек, папки, команды и правила; LICENSE (MIT, если не скажу иначе).
Ограничения: нигде нет настоящих ключей, включая историю git. Работает без ключа ИИ (режим фикстур) и без ключей
оплаты (кнопка показывает «Оплата не настроена»).
Готово, когда: свежий клон запускается через `npm install`, `npm run db:migrate:local`, `npm run dev`;
сборка и тесты зелёные. В конце покажи дерево файлов.
```

Просмотри дерево файлов. Где-то мелькает название финального проекта? Верни агенту. Потом запушь на GitHub и в
**Settings** репозитория отметь **Template repository** — теперь кнопка «Use this template» создаёт чистую копию в один
клик.

> **Если застрял:** если всё время ломается именно оплата, выпусти шаблон сегодня без неё, а шаги опиши в
> `docs/payments.md`. Рабочий шаблон из трёх частей лучше сломанного из четырёх. Схема с уведомлением об оплате
> одинакова у всех провайдеров — поменять ЮKassa на CloudPayments потом можно за вечер.

**Доказательство для задания 1:** ссылка на репозиторий.

### 2. Гонка со временем (20 мин)

Теперь докажи, что это работает. Запусти таймер и создай совершенно новый проект из шаблона — например, самое простое
из того, что ты вчера предлагал в откликах.

```bash
gh repo create my-new-thing --template your-name/starter --private --clone
cd my-new-thing
cp .env.example .dev.vars    # или .env — зависит от стека
npm install && npm run db:migrate:local && npm run dev
```

Дальше попроси агента переименовать приложение, переделать демо-форму под новую идею и задеплоить. Останови таймер,
когда новый проект **живёт по адресу** и вход работает. Меньше 15 минут — отлично. Больше — запиши, какой шаг съел
время: это следующее, что стоит автоматизировать (часто это скрипт `setup`, который задаёт 3 вопроса и сам
подставляет названия).

**Доказательство для задания 2:** твоё время и самый медленный шаг.

### 3. Заметь свои повторы (10 мин)

Пролистай коммиты за 60 дней. Что ты собирал больше двух раз? Админку? «Пришли мне в Telegram, когда случится X»?
Выгрузку в CSV? Эти повторяющиеся задачи — твоя настоящая специализация, и именно за них заказчики платят, сами того
не замечая. **Доказательство для задания 3:** три вещи, которые ты собираешь снова и снова, и какая из них пойдёт в
шаблон следующей.

## Готово, когда…

- [ ] Репозиторий шаблона отмечен как Template repository, работает в режиме фикстур, ссылка вставлена.
- [ ] Ты развернул из него новый живой проект и записал время и самый медленный шаг.
- [ ] Ты назвал три вещи, которые собираешь снова и снова.

**Завтра:** подготовка к запуску. У финального проекта появятся история, набор материалов и план площадок.
