Скрипт из девятого дня работает, но только на твоём ноутбуке и только для тебя. Сегодня он превращается в настоящий
инструмент со ссылкой, которую любой откроет с телефона, — а ключ всё это время остаётся спрятанным. Это момент, когда
«я запустил скрипт» становится «я сделал штуку, которой пользуются люди».

## Почему ключу нельзя жить в браузере

Всё, что страница отдаёт в браузер, публично. Любой нажмёт F12, откроет вкладку Network или исходный код и прочитает
каждую строку — вместе с ключом. А боты круглосуточно сканируют GitHub в поисках утёкших ключей и обычно находят их за
считаные минуты. Ключ во фронтенде — это банковская карта, приклеенная скотчем к витрине.

Решение — **бэкенд**: небольшой код, который работает на сервере под твоим контролем. Браузер отправляет текст
пользователя твоему бэкенду, бэкенд добавляет ключ, вызывает ИИ и возвращает только ответ. Как в ресторане: гости
говорят с официантом, официант — с кухней, и никто не заходит на кухню, чтобы прихватить кассу.

**Serverless** значит, что ты не арендуешь и не настраиваешь целый сервер. Ты загружаешь одну функцию, платформа
запускает её на каждый запрос, а на маленьких объёмах это бесплатно или почти бесплатно. Основной пример у нас —
**Cloudflare Workers**: щедрый бесплатный тариф, быстрый деплой, и HTML можно раздавать оттуда же. **Vercel** —
нормальная альтернатива, идея та же.

Ключ на сервере называется **секретом**: это переменная окружения, которую платформа хранит в зашифрованном виде и
отдаёт твоему коду во время работы. Взрослая версия вчерашнего `.env`.

> **Важно:** в России с 2025 года сайты на Cloudflare у части провайдеров открываются медленно или с перебоями. Если
> твои пользователи там — ту же схему можно развернуть в **Yandex Cloud Functions** (ключ хранится в Lockbox, сервисе
> секретов Yandex Cloud). А если твой провайдер ИИ — GigaChat с его особым сертификатом, связка с Yandex Cloud
> Functions обычно проще. Скажи агенту, какой путь выбрал, — шаги ниже меняются только в командах деплоя.

## По шагам

### 1. Выбери крошечный инструмент (5 мин)

Одно поле, одна кнопка, один полезный ответ. Хорошо заходят такие:

- **«Вежливый отказ»** — вставляешь просьбу, от которой хочешь отказаться, получаешь мягкий, но твёрдый ответ.
- **«С канцелярского на человеческий»** — вставляешь письмо от управляющей компании или банка, получаешь три пункта:
  что от тебя хотят и к какому сроку.
- **«Заголовок для канала»** — вставляешь черновик поста для Telegram, получаешь пять цепляющих заголовков.

Бери то, чем сам воспользуешься на этой неделе. Полезное лучше впечатляющего.

### 2. Собери (50 мин)

```text
Цель: небольшой веб-инструмент «<название>»: пользователь вставляет текст, жмёт одну кнопку и получает <что именно>.

Контекст: деплой на Cloudflare Workers (актуальный Wrangler CLI и конфиг wrangler).
<Или: деплой в Yandex Cloud Functions, ключ в Lockbox, фронтенд на GitHub Pages — тогда настрой CORS только для моего домена.>
Worker отдаёт статичный index.html из папки public/ И обрабатывает POST /api/run.
Вызов ИИ происходит только внутри Worker, ключ — из секрета <ANTHROPIC_API_KEY / OPENROUTER_API_KEY / YANDEX_API_KEY>, модель <какая>. Формат запроса сверь с актуальной документацией провайдера.

Ограничения:
- Ключ никогда не попадает во фронтенд, в логи и в ответы.
- Текст длиннее 2000 символов вежливо отклоняй. Длина ответа — около 500 токенов.
- Нет ключа, API вернул ошибку или запрос завис — показывай спокойное человеческое сообщение, а не простыню ошибок.
- Чистая страница, сначала для телефона: заголовок, одно предложение о том, что делает инструмент, поле ввода, кнопка, блок с результатом и кнопкой «Скопировать», состояние загрузки на кнопке. Весь текст интерфейса на русском.
- Для локальной разработки ключ берётся из .dev.vars, и .dev.vars обязательно в .gitignore.
- В конце объясни путь запроса в 5 коротких пунктах.

Готово, когда: npx wrangler dev запускает инструмент локально, я пользуюсь им по адресу localhost, а git status не показывает никаких секретов.
```

Прочитай пять пунктов: браузер → `/api/run` → Worker добавляет ключ → ИИ → Worker → браузер. Если можешь
пересказать эту цепочку вслух — ты понимаешь, что такое бэкенд.

Ключ в `.dev.vars` впиши сам (формат как у `.env`), потом:

```bash
npx wrangler dev
```

Проверь три случая: нормальный текст, пустое поле и неприлично длинную простыню. Открой DevTools → Network и кликни
по запросу `/api/run`: видно, как уходит твой текст и возвращается ответ, — а ключа нет нигде.

**Доказательство:** вставь главный промпт, который ты дал агенту (с подробностями своего инструмента).

> **Если застрял:** на Windows ошибка вроде «npx.ps1 cannot be loaded because running scripts is disabled» значит,
> что PowerShell по умолчанию запрещает вспомогательные скрипты. Один раз выполни
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, ответь Y и перезапусти терминал. Страница открывается, а
> кнопка ничего не делает — смотри сначала консоль браузера, а потом
> терминал, где запущен `wrangler dev`: серверные ошибки появляются там, а не в браузере. Вставь агенту обе.

### 3. Деплой с секретом (60 мин)

```bash
npx wrangler login
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler deploy
```

`wrangler login` откроет браузер, чтобы подключить аккаунт Cloudflare (хватит бесплатного). Имя секрета бери то,
которое читает твой код: `ANTHROPIC_API_KEY` здесь просто пример. `secret put` попросит вставить ключ прямо в
терминал — не в файл и не в чат. `deploy` напечатает адрес на `workers.dev`. Открой его с телефона и воспользуйся
инструментом по-настоящему. Если выбрал Yandex Cloud Functions, агент проведёт тебя через `yc` CLI — принцип тот же:
код отдельно, ключ отдельно.

Потом закоммить и запушь код в новый репозиторий на GitHub: секрет остаётся на платформе, а не в git.

> **Безопасность:** публичный ИИ-инструмент могут заспамить. Лимит или небольшой баланс из девятого дня — твоя
> страховка, проверь, что он на месте. Если позже раздашь ссылку широко, добавь ограничение частоты запросов — попроси
> агента и сверься с документацией платформы.

**Доказательство:** живая ссылка.

### 4. Один живой человек (20 мин)

Отправь ссылку тому, кому инструмент реально подходит, — и не самому вежливому другу, а самому честному. Попроси
воспользоваться один раз без твоих подсказок, а потом спроси: «Чего ты ждал? Что получилось на самом деле?»

**Доказательство:** его реакция в нескольких предложениях — включая то, что слышать не хотелось.
