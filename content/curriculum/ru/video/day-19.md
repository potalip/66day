Сделать один ролик — ремесло. Сделать пятьдесят и не потерять выходные — инженерия. Сегодня твоя работа перестаёт
быть «видео» и становится «машиной, которая делает видео». На этой идее держится весь остаток трека, вплоть до
собственного пайплайна одной командой на 33-й день.

## Пропсы — дырки в шаблоне

В React **пропсы** (props) — это входные данные компонента. В Remotion один и тот же компонент может отрендерить
тысячу разных роликов, если всё, что меняется — текст, цвета, числа, картинки, — приходит пропсами, а не вписано в код.

- **Схема** — описываешь пропсы через `zod` (`z.object({ title: z.string(), accent: z.string() })`). Remotion Studio
  показывает по ней форму, где их можно править вживую, а кривые данные падают с понятной ошибкой, а не рендерят мусор.
- **`defaultProps`** — значения, которые Studio берёт, если ничего не передали.
- **`--props`** — при рендере передаёшь JSON-файл: `npx remotion render Event out/event-1.mp4 --props=./data/event-1.json`.
- **`calculateMetadata`** — по желанию: длительность считается из пропсов (длинный текст — длиннее ролик).

Вопрос проектирования всегда один: *что меняется от ролика к ролику, а что не должно меняться никогда?* Первое —
пропсы, второе — твой бренд, он остаётся в коде.

## Шаг 1. Шаблон и данные

Пример на сегодня — «Афиша недели» для городского Telegram-канала: пять вертикальных роликов по 8 секунд, по одному
на событие. Макет всегда один, меняются текст и цвет. Если у тебя своя тема (советы по учёбе, рецепты, факты о
продукте) — бери её.

```text
Цель: параметрическая композиция Remotion на JSON и пять файлов данных.
Контекст: проект Remotion в remotion/, там моя вчерашняя композиция Intro (возьми из неё шрифт и цвета бренда).
Ограничения:
- Новая композиция "Event", 1080x1920, 30 fps, 240 кадров. Схема пропсов на zod:
  { day: string (например «Пятница»), title: string (до 40 символов), place: string, time: string («19:30»),
    accent: строка с hex-цветом }.
- Передай schema и разумные defaultProps в <Composition>, чтобы Studio показывал поля для правки.
- Макет: день недели крупно сверху акцентным цветом, название влетает пружиной на 10-м кадре, место и время проявляются с 30-го, внизу полоска прогресса заполняется за всю длительность.
- Если название длиннее 28 символов, через calculateMetadata делай ролик длиной 300 кадров вместо 240.
- Создай remotion/data/events.json — массив из 5 событий моего города, которые я выпишу из настоящей афиши (без «Lorem ipsum», «Событие 1» и выдуманных мероприятий), и отдельные data/event-1.json … event-5.json по одному объекту для CLI.
- Учти, что русские слова длинные: переносы по словам, кегль подстраивается под ширину.
Готово, когда: пропсы редактируются в Studio, а
`npx remotion render Event out/event-1.mp4 --props=./data/event-1.json` рендерит одно событие.
```

Перечитай, что агент написал в событиях, и поправь всё, что звучит казённо, — подписываться под этим тебе. Открой
Studio, поменяй акцентный цвет в форме и посмотри, как ролик обновился. Отрендери один:

```bash
cd remotion
npx remotion render Event out/event-1.mp4 --props=./data/event-1.json
ffprobe -v error -show_entries stream=width,height,nb_frames -show_entries format=duration -of default=noprint_wrappers=1 out/event-1.mp4
```

Ожидаешь 1080×1920 и 8 с (или 10 с для длинного названия). Загрузи один вариант, а `events.json` вставь в комментарий.

> **Если застрял:** ошибка zod при рендере — подарок: она называет конкретное поле, которое не так. Прочитай её,
> прежде чем звать агента. Studio не показывает форму — проверь, что `schema` передана в `<Composition>`, а версия
> `zod` та, которую требует документация Remotion.

## Шаг 2. Все пять одной командой

Можно пять раз вызвать CLI, но тогда проект каждый раз собирается заново. API рендера собирает его один раз:

```text
Цель: скрипт пакетного рендера для шаблона Event.
Контекст: remotion/data/events.json — массив пропсов.
Ограничения:
- remotion/scripts/render-all.mjs на @remotion/bundler (bundle один раз) и @remotion/renderer (selectComposition + renderMedia, codec h264) для каждого элемента.
- Результат — out/events/event-<номер>.mp4. Если файл уже есть, пропускать, кроме запуска с --force.
- Для каждого ролика печатать: имя файла, число кадров, сколько секунд рендерился. В конце — общее и среднее время.
- Добавь npm-скрипт "render:events".
Готово, когда: `npm run render:events` рендерит 5 файлов и печатает таблицу времени.
```

```bash
npm run render:events
for f in out/events/*.mp4; do echo "$f $(ffprobe -v error -show_entries format=duration -of csv=p=0 "$f")"; done
```

Вставь таблицу времени как доказательство. Посмотри на среднее: умножь на сто — столько твой ноутбук будет делать
сотню роликов. Запомни это число: на 40-й день будешь решать, где должен работать рендер.

> **Совет:** запусти скрипт второй раз. Все файлы пропустятся за секунду. Не переделывать уже сделанное — первое
> правило любого пайплайна.

## Мини-тест

Пропс или в коде?

1. Название события в каждом ролике.
2. Частота кадров.
3. Логотип и фирменный шрифт.
4. Цвет фона, если у каждого выпуска рубрики свой цвет.

> **Ответы:**
>
> 1. Пропс — меняется в каждом ролике.
> 2. В коде: разный fps внутри серии даёт ошибки тайминга и ничего не добавляет.
> 3. В коде (или в конфиге бренда, день 32): смысл бренда в том, что он не меняется от ролика к ролику.
> 4. Пропс — если цвет действительно свой у каждого выпуска, это данные. А если вариантов всего три, передавай название
>    («синий»), а не любой hex, чтобы никто не сломал палитру.
