Ты этот стиль точно видел: фиолетовый градиент, эмодзи-ракета, три одинаковые карточки, всё по центру, серый текст на
сером фоне. Агенты рисуют так по умолчанию — это «среднее по интернету». Сегодня у главного экрана появится характер,
а у тебя — цикл, который чинит любой интерфейс: **скриншот → оценка → одна точная правка → снова скриншот.**

## Пять правил продуманного интерфейса

1. **Одно главное действие на экран.** Реши, что человек делает чаще всего (у репетитора — «Добавить занятие»), и
   сделай это единственной залитой кнопкой акцентного цвета. Всё остальное — тише.
2. **Иерархия через размер и насыщенность, а не через цвет.** Один крупный заголовок, понятные подписи разделов,
   основной текст читаемого размера (16 px на телефоне). Если жирное всё — не жирное ничего.
3. **Шкала отступов.** Несколько шагов (4, 8, 16, 24, 32 px — в Tailwind это `p-2`, `p-4`, `gap-6`…) и никаких
   других. Неровные отступы — главная причина, почему экран кажется «каким-то не таким», хотя никто не может сказать почему.
4. **Сдержанная палитра.** Нейтральный фон и текст, один акцент для действий, один цвет для ошибок. Проверь контраст:
   светло-серый на белом многие просто не прочитают.
5. **Настоящие данные и настоящие состояния.** Рисуй на правдоподобных данных («Маша, 7 класс, алгебра — чт 17:00,
   не оплачено»), и продумай **пустое состояние** (первый визит), **загрузку** и **ошибку**. Пустой список с
   дружелюбной подсказкой, с чего начать, — часть продукта, а не мелочь на потом.

**Mobile-first** — значит, сначала проектируешь под экран телефона шириной ~390 px, а уже потом растягиваешь под
десктоп. Большинство пользователей откроют твою ссылку из Telegram, с телефона.

## Шаг за шагом

### 1. Собираем главный экран (40 минут)

Базы данных пока нет, поэтому агент возьмёт небольшой файл с правдоподобными примерами. Завтра заменим его настоящей БД.

```text
Цель: собери главный экран, описанный в docs/SPEC.md.

Контекст: проект на Vite + React + TypeScript + Tailwind. Бэкенда пока нет.

Ограничения:
- Mobile-first: экран должен выглядеть продуманно при ширине 390px, а при 1280px — аккуратно расширяться (ширина контента не больше ~720px, по центру).
- Правила: одно главное действие (акцентный цвет), иерархия через размер и насыщенность, отступы только 4/8/16/24/32px, нейтральная палитра + один акцент, без градиентов, без эмодзи для украшения, без карточек в карточках.
- Положи 6 правдоподобных примеров в src/sampleData.ts (живые имена, даты, пограничные случаи вроде очень длинного названия).
- Сделай пустое состояние (когда список пуст) и кнопки, доступные с клавиатуры, с видимым фокусом.
- Поддержи светлую и тёмную тему через prefers-color-scheme.
- Весь текст интерфейса — на русском.

Сначала объясни план: компоненты, раскладка на обеих ширинах, какие цвета возьмёшь. Дождись моего «ок».
В конце установи Playwright, если его нет, и напиши scripts/screenshot.mjs, который сохраняет скриншоты запущенного приложения в 390x844 и 1280x800 как screenshots/mobile.png и screenshots/desktop.png. Запусти его и назови пути к файлам.
```

Посмотри на скриншоты сам — сначала на телефонный. Загрузи оба как доказательство.

> **Если застрял:** если скрипт падает с «browser not found», попроси агента выполнить
> `npx playwright install chromium` и повторить. Если страница пустая — открой консоль разработчика (F12) и вставь
> агенту красную ошибку.

### 2. Цикл скриншотов: три улучшения (35 минут)

Размытая просьба («сделай покрасивее») даёт случайный результат. Точная — точный. Посмотри на телефонный скриншот и
найди три конкретные проблемы, сверяясь с пятью правилами. Проси по одной:

```text
Посмотри на screenshots/mobile.png. Нужна ровно одна правка:
кнопка «Добавить занятие» выглядит так же, как фильтры-чипсы, и главное действие теряется.
Сделай её единственной залитой акцентной кнопкой на экране, а чипсы — контурными и поменьше.

Перед правкой в двух строках скажи, что поменяешь. После — перезапусти scripts/screenshot.mjs, сохрани результат как screenshots/after-1-mobile.png, посмотри на него и честно скажи, исправлено ли.
```

Хорошие цели для трёх кругов: тесная строка списка, заголовок, который некрасиво переносится, бледный второстепенный
текст, пустое состояние с голым «Нет данных», кнопка меньше ~44 px, в которую не попасть пальцем. Сохрани самое первое
«до» и последнее «после» и загрузи их рядом. Коммить после каждого удачного круга:

```bash
git add -A && git commit -m "UI: clearer primary action" && git push
```

> **Совет:** агенты умеют смотреть на картинки. Вопрос «какое место на этом экране слабее всего по пяти правилам?» —
> отличный способ получить второе мнение. Но решение за тобой.

## Мини-тест

1. На экране три яркие кнопки: «Добавить», «Импорт», «Настройки». Что не так?
2. Второстепенный текст цвета `#BBBBBB` на белом. Почему это проблема и как исправить?
3. На примерах список выглядит отлично, а у нового пользователя при первом входе — белая пустота. Какое правило пропущено?
4. Отступы на странице: 7, 12, 15 и 22 px. О чём попросишь агента?

> **Ответы:**
>
> 1. Три главных действия — значит, ни одного. Выбери самое частое и оставь акцентной только его; остальные сделай
>    второстепенными (контурными или текстовыми).
> 2. Контраст слишком низкий: многим не прочитать, особенно с телефона на улице. Возьми серый потемнее, чтобы проходил
>    проверку контраста WCAG AA (4,5:1 для основного текста).
> 3. Правило 5 — настоящие состояния. Пустому списку нужно короткое пояснение и первое действие («Добавь первого ученика»).
> 4. Привести все отступы к шкале (например, 8, 16, 24) и использовать одинаковый отступ для одинаковых по смыслу связей.
