Театр не открывает сезон в первый же вечер, когда актёры примерили костюмы. Сначала генеральный прогон: весь спектакль,
свет, несколько зрителей и режиссёр с блокнотом. Завтра премьера. Сегодня генеральная — и последний момент, когда ещё
можно сказать «сейчас, только одну штуку поправлю».

## Зачем нужен ритуал v1.0

**Тег в git** — постоянное имя для одного конкретного коммита. Поставить `v1.0.0` — значит сказать: запускается
*вот это*. Если в день запуска что-то пойдёт не так, к нему всегда можно вернуться, а в кейсе потом сошлёшься
именно на него. А **changelog** — простой список того, что и когда изменилось, — показывает пользователям и будущим
заказчикам, что за продуктом стоит живой человек. Номер версии устроен по **семантическому версионированию**:
`МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`. Завтрашнее исправление бага — `v1.0.1`, новая функция через месяц — `v1.1.0`.

## Шаг за шагом

### 1. Пять последних исправлений (35 минут)

Открой список «не сейчас» с 54-го дня (`docs/LATER.md`), чек-лист с 62-го и свежие отзывы. Выбери **ровно пять** пунктов, каждый — на
5–10 минут: опечатка на главной, нет OG-картинки, непонятная подпись на кнопке, медленная первая загрузка, забытый цвет
в тёмной теме. Не новые функции. Дальше:

```text
Цель: финальная шлифовка перед тегом v1.0.0. Исправь эти пять пунктов: [перечисли, по строке на каждый].
Ограничения: минимальное изменение на пункт, по коммиту на каждый с понятным сообщением; без новых зависимостей и рефакторинга. После всех пяти: сборка, все тесты Vitest и Playwright и скрипт скриншотов launch/shoot.mjs; скажи, если какой-то скриншот изменился так, что мне стоит глянуть.
Потом создай CHANGELOG.md в стиле «Keep a Changelog» с разделом v1.0.0 на русском, для пользователей, а не для разработчиков: сгруппируй историю git с первого коммита в «Добавлено / Изменено / Исправлено», не больше 12 пунктов, простыми словами.
Готово, когда: всё зелёное и ты показал мне changelog.
```

Редактируй список изменений, пока он не станет историей, которая интересна пользователю («Теперь планы можно
сохранять и возвращаться к ним»), а не свалкой коммитов. Потом ставь тег и публикуй релиз:

```bash
# когда пять исправлений уже влиты в main
git checkout main && git pull
git tag -a v1.0.0 -m "v1.0.0 — публичный запуск"
git push origin v1.0.0
gh release create v1.0.0 --title "v1.0.0" --notes-file CHANGELOG.md
```

Задеплой в продакшен ровно этот коммит. **Доказательство для задания 1:** ссылка на релиз в GitHub.

> **Если застрял:** тег встал не на тот коммит? Пока им никто не пользуется, удали и создай заново:
> `git tag -d v1.0.0 && git push origin :refs/tags/v1.0.0`, затем тег ещё раз. После запуска теги не двигают —
> делай `v1.0.1`.

### 2. Генеральная репетиция (40 минут)

Найди друга, который приложением **не** пользовался (наблюдатель с 53-го дня не подходит). Воссоздай день запуска как
можно точнее:

1. Отправь ему настоящий пост из `launch/copy.md` (сообщением в Telegram или черновиком) в том виде, в каком его
   увидит незнакомец в канале.
2. Попроси думать вслух: «Говори, что читаешь и чего ждёшь дальше».
3. Смотри, как он идёт **пост → лендинг → регистрация → польза**, лучше со своего телефона. Таймер включается, когда
   он открыл пост. Не помогай.
4. Потом три вопроса: *Что, по-твоему, это делает? Для кого это? Кому бы ты это переслал?*

Запиши общее время, каждое зависание, ответы и всё, что сломалось. Исправь максимум **одно** — самое крупное, остальное
в `v1.0.1`. Репетиция нужна, чтобы найти проблемы, а не чтобы перестраивать сцену.

**Доказательство для задания 2:** твои заметки со временем и тремя ответами.

> **Совет:** попроси агента в день запуска раз в 10 минут гонять тест первого запуска на Playwright против адреса
> в продакшене и слать тебе сообщение в Telegram, если он упал: подойдёт workflow в GitHub Actions по расписанию или Cron
> Trigger в Cloudflare (GitHub иногда запускает такие задачи с опозданием на несколько минут). Пара десятков строк —
> и про падение ты узнаешь раньше пользователей.

### 3. Что такое успех? (15 минут)

Запиши *до* запуска, что для тебя успех, иначе завтра мозг передвинет планку в ту или другую сторону. Три строки:

- **Цифра, которая зависит от тебя:** «Отвечаю на каждый комментарий в течение часа».
- **Цифра, на которую надеешься:** «50 посетителей, 10 регистраций, трое вернулись на второй день».
- **Ощущение:** «Мне не стыдно отправить эту ссылку потенциальному заказчику».

Сверь среднюю строку с целью запуска из `docs/CAPSTONE.md` (50-й день) и честно поправь её, если
бета научила другому. Гарантирована только первая. А важнее всего на 66-й день окажется последняя. **Доказательство для задания 3:** твои
три строки.

- [ ] Друг прошёл всю репетицию; время, зависания и три ответа записаны.
