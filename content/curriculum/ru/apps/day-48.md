Публичный репозиторий — это кусок портфолио, который работает, пока ты спишь. Заказчик с Хабр Фриланса, тимлид на
собеседовании или такой же вайб-кодер из чата открывает его и секунд за десять решает, доводишь ли ты дела до конца.
Сегодня один твой репозиторий пройдёт этот десятисекундный тест, а ты отправишь первый вклад в проект, которым всё
это время бесплатно пользуешься.

## Чем цепляет репозиторий

Люди читают верх README и уходят. Поэтому верх должен по порядку ответить на четыре вопроса:

1. **Что это?** Одно предложение без жаргона: «Telegram-бот, который превращает голосовые в общий список покупок».
2. **Оно работает?** GIF или скриншот в действии — самое убедительное, что вообще может быть на странице.
3. **Как запустить?** Три команды, которые можно скопировать и которые работают на чистой машине.
4. **Можно ли этим пользоваться?** **Лицензия.** Без лицензии действует «все права защищены»: юридически никто не
   может использовать твой код, как бы дружелюбно ни выглядел репозиторий.

Приятные дополнения: короткий раздел «Как это устроено», `.env.example` с объяснением каждой переменной, пара задач
с меткой `good first issue`, описание и темы (topics) на странице репозитория.

**Какой репозиторий выбрать?** Главное приложение, если не жалко его показать. Если оно становится платным продуктом,
открой кусок поменьше и поуниверсальнее: MCP-сервер с 39-го дня, Telegram-бота или вчерашнюю запускалку эвалов.

## Шаг за шагом

### 1. Убедись, что наружу не уйдёт ничего секретного (10 минут)

Это первым делом. Git помнит **всё**, включая `.env`, случайно закоммиченный несколько недель назад и удалённый
на следующий день.

```text
Просканируй репозиторий вместе со всей историей git на секреты: API-ключи, токены, пароли, приватные адреса, реальные данные пользователей. Используй gitleaks, если он есть (или поищи по истории через git log -p типичные шаблоны ключей). Перечисли каждую находку с коммитом и файлом. Историю пока не переписывай — только отчёт.
```

Если нашлось что-то настоящее, **сначала замени ключ**: создай новый у провайдера, старый отзови. Потом вместе с
агентом реши, чистить историю или завести новый публичный репозиторий из текущего кода. Замена ключа не обсуждается:
считай, что утёкший ключ уже кто-то скопировал.

### 2. README, GIF, лицензия, запуск в 3 команды (30 минут)

Запиши 10–20 секунд экрана с главным сценарием (любой программой записи или видео из Playwright) и сделай из этого
лёгкий GIF:

```bash
ffmpeg -i demo.mp4 -vf "fps=12,scale=800:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" docs/demo.gif
```

Целься в размер до 5 МБ, чтобы страница грузилась быстро. Лицензию выбери на choosealicense.com: **MIT** — если
просто хочешь, чтобы твоим кодом пользовались; **Apache-2.0** — если нужна ещё и явная защита от патентных претензий;
**AGPL-3.0** — если хочешь, чтобы каждый, кто запускает изменённую версию как сервис, открывал свои правки.

```text
Цель: сделать репозиторий гостеприимным для незнакомца.
1. Перепиши README.md: описание в одно предложение; сразу под ним docs/demo.gif; «Быстрый старт» ровно из 3 команд (git clone ... && cd ..., npm run setup, npm run dev); «Как это устроено» в 5 пунктах; таблица «Настройки» по .env.example; строка про лицензию. README на русском, а в начале — одна строка на английском для иностранцев.
2. Добавь `npm run setup`: копирует .env.example в .env, если его нет, ставит зависимости, применяет локальные миграции.
3. Проверь, что приложение запускается без единого API-ключа (ИИ-функции показывают «не настроено» и демо-данные).
4. Добавь файл LICENSE (<MIT/Apache-2.0/AGPL-3.0>) с моим именем и годом.
5. Добавь короткий CONTRIBUTING.md (как запускать тесты, как открыть PR) и создай 2 задачи с меткой good first issue.
Готово, когда: в свежем клоне во временной папке эти 3 команды поднимают приложение.
```

А теперь **проверь сам**: склонируй репозиторий в новую папку и выполни три команды. Всё, что сломается у тебя,
сломается и у незнакомца. Сделай репозиторий публичным, добавь описание и 3–5 тем, пришли ссылку.

> **Если застрял:** «у меня всё работает» обычно означает пропущенную переменную в `.env`, неприменённую миграцию
> или глобальную утилиту, поставленную месяц назад и забытую. Попроси агента перечислить все внешние
> зависимости (версия Node, ffmpeg, Python) и вписать их в README с точными версиями.

### 3. Один маленький вклад в чужой проект (25 минут)

За 48 дней через твои руки прошли десятки открытых инструментов. Подари одному из них что-нибудь маленькое и настоящее:

- **Правка документации**: опечатка, битая ссылка, устаревшая команда, на которую ты наткнулся. Отличный вариант —
  русские переводы документации: у ru.react.dev и многих других проектов они делаются сообществом, и неуклюжих
  фраз там хватает.
- **Хороший баг-репорт**: что делали, чего ожидали, что получили, версии, минимальный пример воспроизведения.
- **Маленький PR**: пример, тест, понятнее сообщение об ошибке.

Этикет, при котором тебя вливают, а не игнорируют: сначала прочитай `CONTRIBUTING.md`, поищи похожие задачи,
делай маленькие правки и объясняй *зачем*. Мейнтейнеры тонут в небрежных PR, сгенерированных ИИ. Пользуйся агентом,
но понимай каждую строку и отвечай за неё, а если проект просит, честно пиши, что помогал ИИ. Вдумчивый баг-репорт
всегда лучше небрежного PR.

## Подумай

Посмотри на свой репозиторий глазами человека, который наткнулся на него в статье на Хабре. Напиши 3–5 предложений: что
незнакомец должен заметить первым — и правда ли верх README это показывает? Если нет, поправь прямо сейчас: это
тоже засчитывается.

      проверенным в свежем клоне; ссылка отправлена.
- [ ] В чужом проекте открыта задача или PR; ссылка отправлена.
