В день 26 ты дал два инструмента ИИ *внутри* своего приложения. Сегодня наоборот: ты даёшь ИИ-ассистентам *снаружи*
(Claude Code, Claude Desktop и другим, кто понимает MCP) способ пользоваться твоим приложением. Спрашиваешь агента
«что я добавил за неделю?» — и он просто идёт и смотрит. Это MCP, и после первого своего сервера ты
начнёшь видеть такие разъёмы повсюду.

## MCP на одной схеме

```
 [ ИИ-приложение / агент ]  ── хост, например Claude Code
        │  встроенный MCP-клиент
        │  говорит по MCP (сообщения JSON-RPC)
        ▼
 [ MCP-сервер ]             ── маленькая программа, которую пишешь ты или кто-то ещё
        │  обычный код: HTTP-запросы, SQL, файлы
        ▼
 [ API твоего приложения / база / любой сервис ]
```

**MCP (Model Context Protocol)** — открытый стандарт подключения ИИ-приложений к инструментам и данным. Представь
USB-C: раньше каждому ИИ-приложению нужен был свой провод к каждому сервису, а теперь сервис выпускает один
MCP-сервер, и подключиться может любое приложение с поддержкой MCP.

Сервер может предлагать три вещи:

- **Инструменты (tools)** — действия, которые модель вызывает сама: имя, описание и схема входных данных.
  «create_item», «search_orders». Та же идея, что в дне 26.
- **Ресурсы (resources)** — данные только для чтения, которые приложение подгружает как контекст, по адресу (URI).
  «README», «сегодняшний отчёт».
- **Промпты (prompts)** — готовые шаблоны, которые выбирает пользователь, как слэш-команду. «/weekly-summary».

Серверы работают либо **локально** (хост запускает их как процесс и общается через stdin/stdout, это называется
stdio), либо **удалённо** по HTTP. Сегодня — локально, так проще всего.

## Шаг за шагом

### 1. Подключи готовый сервер (25 мин)

Начни с того, что пригодится сразу: **Playwright MCP** даёт агенту управлять настоящим браузером. В Claude Code:

```bash
claude mcp add playwright -- npx @playwright/mcp@latest
claude mcp list
```

(У других агентов похожая настройка — обычно JSON-файл со списком серверов. Поищи «MCP» в документации своего
агента.) Перезапусти агента и дай ему настоящее задание:

```text
С помощью инструментов Playwright MCP открой мою посадочную страницу <адрес> в ширину 390px. Нажми главную кнопку,
пройди регистрацию тестовым аккаунтом и сообщи обо всём, что сломано или непонятно. Сделай скриншот каждого шага.
```

Обрати внимание: перед каждым вызовом инструмента агент спрашивает разрешения — так хост тебя защищает. Для задания 2
вставь: какой сервер подключил, о чём попросил и что он нашёл.

> **Безопасность:** MCP-сервер работает с твоими правами. Ставь только серверы из надёжных источников (официальные
> репозитории, известные компании), смотри, какие инструменты они открывают, и никогда не вписывай токены в
> конфиг, который уйдёт в коммит.

### 2. Свой сервер: два инструмента (60 мин)

Свой сервер положи в папку `mcp/` репозитория (`main-app/mcp/`, рядом с `bot/`). Он ходит в **API твоего приложения** с
личным токеном. Так он подчиняется той же авторизации и тем же лимитам, что и само приложение.

Выбери два инструмента: один **читает**, другой **пишет**. Например, `list_recent_items` и `add_item`.

```text
Цель: крошечный MCP-сервер для моего приложения на TypeScript на официальном MCP TypeScript SDK
(@modelcontextprotocol/sdk), схемы входа на zod, транспорт stdio. Актуальные имена пакетов, пути импорта и API сверь с README SDK (между мажорными версиями они
меняются).
Контекст: API приложения по адресу APP_URL, эндпоинты <перечисли>; авторизация токеном из переменной APP_TOKEN.
Добавь в приложение POST /api/tokens: вошедший пользователь создаёт личный токен (храним только хеш), а API
пусть принимает «Authorization: Bearer <токен>» вместо сессионной cookie и узнаёт по нему пользователя.
Инструменты:
1. list_recent_items: вход { limit: целое 1–50, по умолчанию 10 }; возвращает короткий читаемый список.
2. add_item: вход { title: строка 1–200 символов, note?: строка }; создаёт запись через API; возвращает id и ссылку.
Ограничения:
- Понятные описания инструментов, написанные для модели: когда вызывать и что вернётся.
- Проверка входа; ошибки API превращаются в читаемые ошибки инструмента (isError), сервер не падает.
- Никаких логов в stdout (по нему идёт протокол) — только stderr.
- README: как собрать, как подключить к Claude Code, какие нужны переменные.
Готово, когда: всё работает в MCP Inspector и в Claude Code.
```

Удобнее на Python? Попроси то же самое на официальном Python SDK с `FastMCP` и декораторами `@mcp.tool()`.

Проверь в **MCP Inspector** — маленьком веб-интерфейсе для отладки серверов:

```bash
npm run build
npx @modelcontextprotocol/inspector node build/index.js
```

Вызови каждый инструмент руками. Потом подключи сервер к агенту:

```bash
claude mcp add myapp -e APP_URL=https://your-app.example -e APP_TOKEN=your-token -- node /full/path/to/build/index.js
```

Токен оседает в локальном конфиге Claude Code, а не в репозитории. Не добавляй здесь `--scope project`: так
создаётся `.mcp.json`, который как раз коммитят. Теперь попроси обычными словами: *«Добавь запись „Попробовать MCP“ и покажи пять последних»*. Посмотри, как агент сам
выбирает твои инструменты по их описаниям. Запушь сервер и вставь ссылку на репозиторий для задания 3.

> **Если застрял:** агент не видит инструменты? Запусти `claude mcp list` и посмотри статус. Чаще всего виноваты
> относительный путь (нужен абсолютный), забытая сборка или что-то, что печатает в stdout. Ошибки «Invalid JSON»
> значат именно последнее: найди забытый `console.log` и замени на `console.error`.

> **Совет:** относись к `add_item` как к любому пишущему инструменту: токен принадлежит одному пользователю, API
> проверяет владельца, хост спрашивает перед вызовом. Всё из дня 33 по-прежнему в силе.

## Мини-тест

1. «Найти мои заказы по имени клиента» — инструмент, ресурс или промпт?
2. «Список изменений приложения, доступный как контекст» — что это?
3. «Шаблон /weekly-review, который пользователь выбирает из меню» — что это?
4. Почему MCP-серверу лучше ходить в API приложения, а не напрямую в базу?

<details><summary>Ответы</summary>

1. Инструмент: действие со входными данными, которое модель решает вызвать.
2. Ресурс: данные только для чтения, подгружаемые как контекст.
3. Промпт: шаблон, который выбирает пользователь.
4. API уже проверяет вход, владельца, данные и частоту запросов. В обход API пропадает вся твоя защита.

</details>
