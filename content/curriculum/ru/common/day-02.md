Вчерашняя страница живёт в одной папке на одном ноутбуке. Сегодня у неё появится адрес в интернете. Большинство
тех, кто «хочет научиться программировать», так ничего и не выпускают. Ты выпустишь на второй день.

## Как страница попадает из папки по ссылке

Три детали и одна аналогия:

- **Git** — система сохранений, как в игре, только для папки. Каждый **коммит** — сохранение с подписью, к которому
  можно вернуться.
- **GitHub** — полка в облаке, где лежат твои сохранения. Папка под присмотром git называется **репозиторием**
  (репо), а отправка коммитов на GitHub — **пушем**.
- **GitHub Pages** — бесплатная витрина: показываешь ей репозиторий с `index.html`, и GitHub отдаёт его по адресу
  `https://<твой-логин>.github.io/<имя-репозитория>/`.

Команды git наберёт агент. Твоя задача — понимать, зачем нужен каждый шаг, и проверять результат.

## Шаг 1. Аккаунт на GitHub (10 минут)

Зарегистрируйся на github.com. Логин выбирай с умом: он будет в каждой ссылке, которую ты отправишь, так что
`katya-builds` лучше, чем `kotik_2007`. GitHub попросит включить двухфакторную защиту — включай, проще всего через
приложение-аутентификатор.

> **Важно:** GitHub работает и из России. Платные функции российской картой не оплатить, но всё, что нужно в
> программе, бесплатно.

## Шаг 2. Инструменты: git и GitHub CLI (10 минут)

Проверь, есть ли git: `git --version`. Доставь недостающее. `gh` — консольная утилита GitHub: она берёт вход на
себя, и пароли в терминал вводить не придётся.

```bash
# macOS: ставим Homebrew — стандартный менеджер пакетов для Mac (git он подтянет сам),
# выполняем строки из «Next steps» в конце его вывода, затем ставим gh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install gh

# Windows
winget install --id Git.Git -e
winget install --id GitHub.cli -e

# Ubuntu / Debian
sudo apt update
sudo apt install git gh
```

Если на Linux apt не находит `gh`, поставь его по инструкции для Linux на cli.github.com. Перезапусти терминал, войди и представься git:

```bash
gh auth login
git config --global user.name "Katya Smirnova"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

Последняя строка нужна, чтобы новые проекты начинались с ветки `main`: некоторые версии git по старинке называют её
`master`. В `gh auth login` выбирай GitHub.com → HTTPS → Login with a web browser. Вместо настоящей почты можно указать
приватный адрес `…@users.noreply.github.com` из Settings → Emails — тогда твой ящик не засветится в истории.

## Шаг 3. Пушим вместе с агентом (15 минут)

Перейди в папку проекта, запусти агента и отправь ему промпт:

```bash
cd ~/66-day-promise
claude
```

```text
Цель: выложи эту папку на GitHub как публичный репозиторий 66-day-promise.

Контекст: я новичок. git и GitHub CLI (gh) установлены, вход через gh выполнен.
В папке лежит моя страница index.html.

Ограничения: перед каждой командой объясни одним простым предложением, что она делает.
Сделай первый коммит с понятным сообщением. Кроме короткого README.md о том, что это
за страница, никаких файлов не добавляй.

Готово, когда: репозиторий создан на GitHub, коммит запушен, а ты вывел ссылку на репозиторий.
```

Открой ссылку. На GitHub должны быть видны `index.html` и `README.md`.

**Доказательство:** ссылка на репозиторий, например `https://github.com/katya-builds/66-day-promise`.

## Шаг 4. Включаем Pages (10 минут)

На странице репозитория: **Settings → Pages**. В блоке `Build and deployment` выбери Source **Deploy from a
branch**, ветку **main** (если в списке только `master` — выбирай её), папку **/ (root)** и нажми **Save**. Подожди минуту-другую и обнови страницу — появится
плашка с живым адресом. Открой его и с телефона: это главный экзамен.

> **Если застрял:** 404 обычно значит «ещё не готово» — подожди пару минут. Всё ещё 404? Проверь, что файл
> называется ровно `index.html` (строчными) и лежит в корне репозитория, а не во вложенной папке. Во вкладке
> *Actions* видна каждая публикация; у красной есть лог — скопируй его агенту с вопросом «что пошло не так?».

> **Безопасность:** публичный репозиторий и сайт на Pages видят все. Телефон, домашний адрес и всё, о чём
> пожалеешь, — не на страницу. И правило навсегда: пароли и API-ключи никогда не попадают в репозиторий.

**Доказательство:** живая ссылка, например `https://katya-builds.github.io/66-day-promise/`.

## Шаг 5. Покажи одному человеку (10 минут)

Скинь ссылку в Telegram одному человеку: другу, сестре, коллеге. Не спрашивай «ну как?» — услышишь «прикольно».
Лучше так: «Начинаю 66-дневный челлендж — учусь делать штуки с ИИ. Это второй день. Что тебе первым бросается в
глаза?» Запиши ответ, по возможности дословно.

- [ ] Ты вставил ссылку на репозиторий.
- [ ] Ты вставил живую ссылку на GitHub Pages и открыл её с телефона.
